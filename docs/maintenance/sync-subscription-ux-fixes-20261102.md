# 캘린더 구독 오류 수정 — 2026-11-02

2026-11-02 인터페이스 점검에서 재현한 네 가지 오류를 수정했다. 기존 개인 DB와 계정은 변경하지 않고 현재 소스와 격리된 합성 데이터로 검증했다. 제품 버전은 4.8.0을 유지한다.

## 보관 동작과 데이터 안전성

- `calendar_repo.archive_ics_subscription()`은 기존 일정 ID, 내용과 연결된 데이터를 유지한다. 새 로컬 캘린더에는 원본 구독 주소나 동기화 식별자를 보관하지 않는다.
- 보관 캘린더는 일반 로컬 캘린더이며 이름은 `원래 이름 · 보관`, 초기 상태는 `표시 안 함`이다. `캘린더 관리 → 로컬 캘린더 → 보관 캘린더 → 일정 화면에 표시`에서 다시 볼 수 있다.
- 구독 해제 확인창에 숨김 보관 동작과 다시 표시하는 경로를 알린다. 기본 응답은 취소이며 원본 서비스에는 삭제 요청을 보내지 않는다.
- 보관 캘린더 생성·일정 이동·구독 정보 제거는 하나의 SQLite SAVEPOINT로 묶었다. 어느 단계든 실패하면 해당 작업을 되돌리고 호출자의 기존 트랜잭션은 보존한다.
- 일반 `delete_calendar()`로 ICS 삭제가 요청되는 호환 경로도 같은 보관 처리를 사용한다. 일정이 없는 구독은 빈 보관 캘린더를 만들지 않는다.
- 늦게 도착한 구독 갱신 결과와 재구독이 사용자가 수정한 보관 사본을 덮어쓰지 않는 것을 검증했다. DB 스키마 변경은 없다.

보관 사본과 재구독 사본은 물리적으로 별도 유지한다. 기본 숨김으로 중복 표시를 방지하며, 사용자가 보관 캘린더를 다시 표시하면 두 사본을 함께 볼 수 있다. 과거 버전에서 이미 출처 연결이 사라진 사본은 안전하게 원본을 판별할 수 없어 자동 병합·삭제하지 않는다.
