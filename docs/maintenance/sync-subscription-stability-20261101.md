# 캘린더 동기화·구독 안정화 — 2026-11-01

상태: 소스 수정·격리 검증 완료. 제품 기준 번호 4.8.0 유지.

## 재현한 문제와 변경

| 재현 조건 | 기존 문제 | 변경 결과 |
|---|---|---|
| ICS 수신 중 구독 주소 수정·새 구독 추가·개별 갱신 | 진행 중이라는 이유로 후속 요청을 버림 | 기존 coordinator에서 대상 ID를 합쳐 워커 종료 후 최신 구독으로 한 번 실행 |
| Outlook 연결 해제 워커 시작 거부·실패 | 화면에서 이미 가져오기·권한·자동 설정을 변경 | 화면은 실행만 요청하며 DB 처리는 기존 워커에서 수행 |
| CalDAV 연결 해제 또는 완료 signal 직전 앱 종료 | 기존 캘린더가 쓰기 가능한 상태로 남음 | 워커에서 계정 소속 캘린더의 활성·쓰기 권한 해제를 저장한 뒤 완료 통지 |
| 해제 도중 DB 잠금·인증 파일 제거 실패 | 인증과 DB 상태가 서로 어긋날 수 있음 | DB 잠금·권한 변경 후 인증 파일 제거, 제거 실패 시 DB rollback |
| 같은 계정의 재인증 | 미해결 캘린더 오류를 해결된 것처럼 지움 | 기존 오류·성공 시각 보존, 실제 동기화 결과로 해소 |
| 다른 계정 연결·연결 해제 | 이전 계정의 처리 건수·성공 시각이 남음 | 계정 변경 시 처리 요약·성공 시각 초기화 |

ICS 후속 실행은 기존 coordinator와 워커를 사용한다. 자동 갱신 일시정지 중에도 명시한
개별 수동 요청은 실행하며, 삭제·비활성 구독은 실행 직전 다시 제외한다. 전체/자동 중복 요청은
추가 실행하지 않고, 중단하면 대기 중인 대상도 비운다. 기존 원문 검증·주소 대조·스냅샷
트랜잭션·구독별 오류 병합은 같은 경로를 사용한다.

Outlook·CalDAV의 `deactivate()`는 savepoint로 변경해 상위 트랜잭션을 보존한다. 계정에 소속된
캘린더의 선택·권한만 변경하며 다른 계정, 일정 행, 원격 링크와 기존 삭제/생성 확인 대기열을
유지한다. 테이블 DDL·DB 스키마·원격 생성/수정/삭제 계약은 변경하지 않는다.

## 재현 및 검증 근거

- 최초 신규 재현 22건 중 18건 실패: `artifacts/sync-subscription-stability-20261101/reproduction/`.
- 1차 수정 후 종료·DB 잠금·외부 트랜잭션 보존 12건을 추가하자 9건 실패. 워커에서 처리하도록
  보완한 뒤 기존 관련 9개 파일 204건 통과: `disconnect-race-before/`, `worker-recovery/`.
- 신규 검사는 36건이다. 계정별 해제·해제 실패·DB 잠금·다른 계정 보존·삭제 대기열 보존,
  재인증·계정 전환, ICS 대상 병합·중단·비활성/삭제 재확인을 포함한다.
- 실제 QThread·SQLite를 연결한 주소 변경 경합 검사 2건에서 구 주소 수신과 새 주소 요청이
  겹쳐도 최신 주소를 한 번만 조회함을 확인했다. 새 피드 실패 시 기존 일정 ID·내용과 마지막
  전체 성공 시각이 유지되고, 성공한 경우 같은 ID의 일정이 갱신된다.
- 최종 서비스 공통·Google·Outlook·CalDAV·ICS·보안·인코딩 회귀 **62개 파일 1,350건 통과**,
  실패·오류·건너뜀 0건. 파일별 결과와 XML·로그는
  `artifacts/sync-subscription-stability-20261101/regression/results.json`에 보존한다.
- 변경 Python 파일의 Ruff 검사·포맷 검사와 전체 encoding guard 통과.

검사는 검증된 SQLite 3.54.1 프라이빗 Python에서 파일별 별도 프로세스로 실행했다. 임시 DB·INI
QSettings·사용자/공유 경로를 사용하고 외부 네트워크를 차단했다. 기존 HTTP 통합 검사는 합성
루프백 서버를 사용하며 주소 변경 경합은 합성 응답으로 검증했다. 실제 사용자 DB·QSettings·
계정·인증 파일은 이 검증에서 변경하지 않았다.

## 반영 범위와 후속

이번 결과는 개발 소스·격리 Qt/DB/HTTP 검증이다. 실제 서비스 계정의 전체 동기화나 설치판
인수·빌드·GitHub 공개·Store 제출/설치를 완료한 것으로 표시하지 않는다. 다음 통합 배포 때
전체 실행 입력에 포함하고, 설치판의 재연결·오프라인 복귀는 별도로 인수한다.
