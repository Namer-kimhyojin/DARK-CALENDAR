## 재현·수정과 검증

Windows 글꼴 조건에서 긴 동기화 안내문의 지연 줄바꿈이 끝나기 전에 스크롤을 검사하는 문제를 재현했다. 재배치가 완료되면 스크롤과 버튼 접근이 정상임을 확인하고 기존 검사가 최대 1초 안에서 재배치를 기다리도록 보완했다. 기준을 완화하거나 실패 항목을 제외하지 않았다. 관련 21개가 통과했고 `20261019-sync-long-guidance-layout-wait`를 4.1.1 Dev로 등록했다.

기본 글꼴이 스톱워치의 ▶·Ⅱ·■ 기호를 포함하지 않는 경우도 재현했다. 기호를 지원하는 설치 글꼴을 선택하고 기호별 결과를 캐시하도록 수정했다. 실제 렌더링에 사용한 글꼴의 기호 지원을 검사한다. 관련 렌더링 18개와 직접 영향 8개 파일 327개가 통과했으며 `20261019-stopwatch-supported-status-font`를 4.1.2 Dev로 등록했다.

파일별 프로세스로 통합 검사를 수행했다. 긴 기존 검사에 맞춰 제한 시간을 보정하고 완료 결과의 소스·검사 해시가 같은 경우 재사용했다. 최종 234개 파일·4,225개 JUnit testcase가 실패·오류·건너뜀 없이 통과했다. 수정 뒤 직접 영향 결과로 이전 결과를 대체했고 반복 실행은 합산하지 않았다. 실제 사용자 저장소와 외부 네트워크 쓰기를 격리했다.

커밋 훅에 필요한 기존 20개 파일의 서식을 정규화했다. 49개 릴리스 Python 입력의 AST가 같음을 확인했다. 포맷 이전 frozen 비교에서는 `ui_components` 한 모듈의 fingerprint가 달라 최종 소스로 다시 빌드했다. 첫 4.2.0 예약·로컬 준비는 게시·업로드 전에 대체했고, 최종 Store 준비 ID `store-cycle-20261005-final-inputs`로 **4.3.0**을 예약했다. 재시도에는 이 최종 예약을 재사용한다.
