# 시작 속도와 루프 믹서 진입점 보완

2026-11-06 개발 소스 수정 기록입니다. 공개된 5.0.2 패키지를 교체하거나 제품 번호를 올리는 작업은 포함하지 않습니다.

## 사용자에게 보이는 변경

- 상단 **위젯 → 루프 믹서 위젯 열기**에서 독립 믹서를 바로 엽니다. 일반 키덱과 비트메이커 키덱의 우클릭 메뉴에도 같은 항목을 둡니다.
- 이미 만든 믹서가 있으면 그 창을 표시하고 앞으로 가져옵니다. 반복 선택으로 믹서를 계속 만들지 않습니다. 잠금 중에는 실행을 막습니다.
- 위젯 관리자에서 추가하는 기존 경로도 유지합니다. 믹서 안의 **+ 키덱**에서 드럼·멜로디 키덱을 추가할 수 있습니다.
- Windows 기본 시작 경로의 글꼴 초기화 대기를 줄였습니다. 사용자 글꼴·글자 크기·배율 설정과 DB 초기화·동기화·종료 순서는 유지합니다.

사용자가 실행하던 프로세스는 `D:\00. Dev_Folder\Dark Calendar\main.py`였고, 새 믹서 코드는 별도 C: 작업 폴더에만 있었습니다. 두 폴더의 관련 파일을 기준 커밋과 대조해 기존 D: 변경과 충돌하지 않는 명시된 파일만 반영합니다. 백업과 SHA-256 읽기 확인 결과는 `artifacts/startup-optimization-20261106/source-promotion/`에 보관합니다. 실행 중인 사용자 앱을 강제 종료하지 않습니다. **앱을 트레이까지 완전히 종료한 뒤 D: 폴더의 `run.bat`을 다시 실행해야 새 메뉴와 시작 정책을 읽습니다.**

## 측정한 원인과 개선 범위

이 PC의 Python 3.14.10·Qt 6.12.0 실행 환경에서 기본 Windows 글꼴 엔진의 첫 글꼴 조회가 오래 걸렸습니다. 스플래시 색상을 구하는 과정에서도 공통 테마가 글꼴 메트릭을 조회하므로 메인 창 생성 전부터 지연됐습니다. DB 작업 자체는 비교 표본에서 약 23–43ms였습니다.

동일 PC의 임시 프로필·새 DB·계정과 위젯 없는 Windows 창 실행에서 측정했습니다. 시점은 측정 프로세스 시작부터 실제 `OverlayApp.first_paint`까지입니다.

| 경로 | 메인 창 첫 그리기 | 근거 디렉터리 |
|---|---:|---|
| Qt 기본 Windows 경로, 다른 글꼴 검사와 겹치지 않은 표본 | 33.785초 | `full-default-r2` |
| 앱의 개선된 기본 경로, 표본 1 | 4.128초 | `full-app-default-r1` |
| 앱의 개선된 기본 경로, 표본 2 | 4.033초 | `full-app-default-r2` |
| 앱의 개선된 기본 경로, 표본 3 | 4.406초 | `full-app-default-r3` |

측정 파일은 `artifacts/startup-optimization-20261106/`에 있습니다. 별도 최소 글꼴 조회 검사도 Qt 기본 28.326초, GDI 0.403초로 같은 원인을 뒷받침했습니다. 다른 글꼴 검사와 겹친 기본 경로 표본 `full-default-r1`의 54.461초는 비교에서 제외하고 원본을 보존했습니다.

이 값은 `run.bat`의 사전 Python/SQLite 검사, 실제 사용자 계정·데이터·다수 위젯, 설치 패키지, 재부팅 직후의 실행 시간을 포함하지 않습니다. 글꼴 캐시를 지우거나 Windows 서비스를 변경하지 않았습니다. 모든 PC에서 같은 초 단위 개선을 보장하는 수치는 아닙니다.

## 구현과 되돌리기

`calendar_app/infrastructure/runtime/qt_startup_options.py`가 Qt를 import하지 않는 순수 함수로 인자를 결정합니다. `bootstrap.run()`은 QApplication을 만들기 전에 이 결과를 전달합니다. Windows에서 명시적 플랫폼 선택이 없을 때만 `-platform windows:fontengine=gdi`를 추가합니다. 플랫폼·글꼴 환경 변수를 영구 저장하거나 바꾸지 않습니다.

- 사용자가 지정한 `-platform`/`--platform`, `QT_QPA_PLATFORM`, offscreen·minimal 및 플랫폼 대체 목록은 그대로 보존합니다.
- Qt 플러그인 검색 경로는 그대로 유지합니다. PyInstaller의 플러그인 경로만 있다는 이유로 개선 경로를 끄지 않습니다.
- 진단용 `AIR_CALENDAR_FONT_ENGINE=default`는 앱의 기본 선택을 끄고 Qt 기본으로 돌아갑니다. `gdi`를 명시할 수도 있습니다. `directwrite`는 Qt 6.12가 지원하는 `fontengine=native` 인자로 변환합니다. 알 수 없는 값은 Qt 기본을 유지합니다.
- 시작 로그에는 고정된 정책·사유만 기록합니다. 사용자 CLI나 플랫폼 값 전체를 로그에 노출하지 않습니다.

Qt의 Windows 플랫폼 옵션은 [QGuiApplication 문서](https://doc.qt.io/qt-6/qguiapplication.html)와 [Qt 6.12 Windows 구현](https://github.com/qt/qtbase/blob/v6.12.0/src/plugins/platforms/windows/qwindowsintegration.cpp)을 확인했습니다.

## 회귀 검사와 한계

시작 정책 84건, bootstrap 인자·호출 순서·로그 보호 8건을 추가했습니다. 시작 실패·스플래시·DB 진단·종료·레이아웃·동기화·위젯을 포함한 관련 194건과 진입점 관련 55건이 통과했습니다. 임시 INI를 사용하고 실제 사용자 설정·일정 DB·네트워크·오디오 장치 접근을 차단했습니다. 실행 경로 반영 후에는 D: 모듈이 실제 import되는지 별도로 검사합니다.

Windows 글꼴 검사는 실제 배율 100·125·200%에서 한국어·영어·일본어·중국어·아랍어·힌디어·태국어·이모지를 확인했습니다. 세 글꼴×여덟 문자열×세 배율의 72행에서 누락 글리프가 없었고, 앱에서 쓰는 QtAwesome 아이콘도 렌더링했습니다. 엔진 간 일부 문자열 폭은 달라질 수 있어 픽셀 단위 동일성을 보장하지 않습니다.

초기 측정 도구가 첫 paint 신호 안에서 화면을 잡으면서 발생시킨 재귀 그리기 경고는 QA 도구에서 화면 캡처를 이벤트 루프 복귀 뒤로 옮겨 수정했습니다. 표의 첫 paint 시각은 이 캡처보다 앞서 기록했습니다. 후속 검사는 QtAwesome의 세션 글꼴 등록을 피하고 프로세스 전용 Qt 글꼴 로딩을 사용합니다. 초기 도구가 추가한 임시 세션 글꼴은 정확한 소유 경로별 정리 내역을 별도 보존합니다. 제품의 QtAwesome 동작을 임의로 바꾸지는 않았습니다.

실제 사용자 프로필의 재실행 시간, 마이크 청취·터치 하드웨어와 새 설치 패키지는 이번 격리 검사와 별개입니다.
