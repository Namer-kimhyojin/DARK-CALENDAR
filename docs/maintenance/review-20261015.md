# 2026-10-15 11일차 DB·공유 DB·ICS·데이터 보존 점검

10/15 새벽 정기 실행에서 실제 배타적 잠금을 유지하고 1~10일차 완료 기록과 예정일을 대조했다. 당일 범위는 SQLite 캘린더 이관, 공유 DB의 실패 복구, ICS의 전체 스냅샷 반영과 구독 UI·설정 흐름이다. 데이터 손실을 유발하는 실제 계정 쓰기나 사용자 DB 변경으로 오류를 재현하지 않았다.

## 캘린더 이관 실패 복구 수정(P2)

`calendar_repo.migrate_from_gcal_subscription()`은 캘린더 추가나 태스크 귀속 변경 도중 실패해도 앞선 SQL을 되돌리지 않았다. 이후 다른 저장이 부분 이관을 커밋하면, 재시작 시 캘린더가 있다는 이유로 이관을 건너뛰어 일부 태스크의 귀속 복구가 누락될 수 있었다. 성공 시의 전체 `conn.commit()`도 호출자가 저장을 결정해야 하는 다른 작업까지 커밋했다. 캘린더 테이블 조회와 설정 읽기가 오류 처리 밖에 있어 시작 실패를 정상 실패 결과로 반환하지 못하는 경로도 재현했다.

이관 전체에 SQLite SAVEPOINT를 사용한다. 실패 시 이관에서 바뀐 캘린더와 태스크 귀속만 되돌리고, 바깥 트랜잭션은 보존한다. 바깥 트랜잭션이 없으면 성공한 이관을 저장하고, 있으면 호출자가 커밋을 결정한다. 테이블·설정 조회도 같은 오류 처리에 포함했다. 기존 캘린더가 있으면 변경하지 않는 계약과 원본 `gcal_subscription`, 명시된 태스크 캘린더, 읽기 전용 권한 및 기본 캘린더 규칙은 유지했다. 기존 DDL·사용자 설정은 변경하지 않았다.

새 검사 19개 중 수정 전 12개 실패·7개 통과, 수정 후 19개 모두 통과했다. 암묵적 트랜잭션과 autocommit 연결을 각각 확인했다. 두 번째 캘린더 삽입 실패, 앞선 태스크 수정 후 다음 수정 실패, 다른 저장 후 재시도, 바깥 저장의 성공/실패 후 롤백, 기존 캘린더 보존, 스키마·설정 실패와 로컬 기본 생성이 포함된다.

## 공유 DB·ICS 및 관련 검증

격리 기능 검사 196개 통과: 새 이관 19개, 공유 DB·기존 데이터 경계 등 33개, ICS 스냅샷 35개·경계 29개·오류 8개·시간대 5개·UI 통합 1개, 기본 캘린더 27개·설정 보존 30개, DB 후크 3개·조회 6개. 인코딩 12개·컴파일 가드·변경 범위 Ruff·diff 검사도 통과했다.

공유 DB의 초기화 실패 후 재시도와 삭제 실패 시 태스크 귀속 복구를 확인했다. ICS의 불량·부분 응답, 시간 초과·취소·반복 일정·중복 원격 ID·계정/구독 변경 경계는 기존 캐시 보존과 원자 반영 검사를 통과해 새 구현 변경 근거가 없었다. ICS 구독 UI 통합 검사는 선택·설정·공통 갱신 흐름의 격리 검사이며 실제 서버/계정 UI 조작과 구분한다.

개인 DB·QSettings·인증 경로를 임시 폴더로 격리했다. 공유 DB는 `PUBLIC` 환경 변수만으로 격리되지 않는 고정 경로이므로 모듈의 `SHARED_DIR`, `SHARED_DB_PATH`, 연결 캐시도 임시 경로로 바꾼 검사 실행기를 사용했다. 각 검사에서 실제 사용자 설정 보존을 확인했다. 원본 공용 DB·계정으로 저장 테스트를 하지 않았다.
