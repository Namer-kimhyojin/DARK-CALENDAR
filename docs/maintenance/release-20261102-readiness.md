10/31 후속: 13일차 아이콘 대비 오류 2건 수정과 총 522건 검증을 마쳤다. 별도로 등록된 Google 갱신 복구와 날씨 프리미엄 UI도 배포 목록에 연결했다. 현재 **13/14 영역 점검 완료·미배포 후보 9건·관리 입력 680개·Git 미추적 실행 파일 6개**이며, 11/01 집계와 최종 전체 패키지 검증이 남았다. [10/31 근거](review-20261031.md).

10/30 후속: 12일차 동기화·인증·오프라인은 관련 742건·격리 화면 4건·인코딩 12건 통과, 추가 제품 수정 없이 점검 완료했다. 현재 **12/14 영역 완료**, 10/31·11/01 영역과 최종 배포 검증이 남았다. 기존 입력 범위·신규 후보 5건·최종 커밋에 포함할 새 실행 파일 3개는 유지한다. [10/30 근거](review-20261030.md).

**현재까지 구현한 변경은 전체 개발 입력에 존재하며, 미배포 후보 9건과 겹치는 후속 변경을 변경 이력에 연결했다. 아직 최종 패키지를 만들거나 제출한 단계는 아니다.** 11/01 점검에서 추가로 검증된 변경도 같은 배포 묶음에 합친다. 미완료·검증 실패·인증 차단이 남으면 일부 기능을 빼고 배포하지 않고 다음 새벽에 이어간다.

## 누락 방지 근거와 남은 반영 단계

- 10/29 최초 대조는 관리 입력 677개·미등록 0개, 공개 태그 예약 입력 대비 추가 4개·수정 31개·삭제 0개였다. 10/31에는 새 날씨 모듈/스크립트까지 **680개**로 늘었고 후속 이력을 등록했다. 최종 입력 확정 때 읽기 전용 `scan --strict`를 다시 통과해야 한다.
- 최초 5건 후보의 코드가 이후 날씨 번역·아이콘 수정과 겹치면 원래 등록 해시와 달라질 수 있다. 원래 해시는 보존하고 겹친 파일·후속 등록 ID를 연결한다. 현재 후보 9건의 통합 결과는 최종 전체 입력으로 다시 검증한다. 문서만 누적된 해시 차이는 실행 코드 변경과 구분한다.
- Git에 아직 추가되지 않은 실행 입력 **6개**는 기존 `calendar_app/domain/beatmaker_recording.py`, `calendar_app/presentation/widgets/keydeck/beatmaker_dialog.py`, `scripts/run_development.py`와 새 `calendar_app/infrastructure/weather/request_pool.py`, `calendar_app/presentation/widgets/weather_scene.py`, `scripts/validate_weather_premium.py`다. **최종 릴리스 커밋에 이 파일과 관련 새 테스트를 반드시 포함하고, 푸시된 입력과 개발 입력을 재대조해야 한다.** 현재 상태로 원격 빌드를 먼저 실행하지 않는다.
- 677개 목록 외의 루트 아이콘·빌드 정리기·라이선스·소스 제공 문서·CI 등 **10개 지원 파일**도 별도 확인했다. 기존 공개 태그와 다른 README·SOURCE_OFFER·후보 검증 workflow를 포함해 최종 커밋을 확정한다. `scan` 통과만으로 이 별도 지원 범위까지 전부 확정됐다고 해석하지 않는다.
- 실행 입력에서 개인 DB·토큰·계정·사용자 설정·점검 산출물은 제외한다. 사용자 문서 정리·삭제 작업은 기능 입력과 구분해 보존한다.
- 기존 Esc 선택 해제 후보의 오래된 `미배포` 표시는 공개 4.7.1의 실제 컴파일 모듈과 현재 구현 일치로 정정한다. 새 변경이나 재제출 사유가 아니다.

## 버전·인증·외부 대기

- 현재 제품 기준/마지막 GitHub·Store 공개는 **4.7.1**, 이 PC 설치는 **4.7.1.0**이다. 같은 번호의 개발 소스에 미배포 변경이 있으므로 번호만으로 파일 동일성을 판단하지 않는다.
- 녹음·루프 기능 추가를 포함한 현재 범위라면 현행 규칙상 **4.8.0을 우선 검토**한다. 아직 예약하지 않았으며 최종 범위 확정 때 `prepare`로 한 번 결정한다. 동일 후보 재시도는 같은 버전·파일·ID를 재사용한다.
- Store 서버 마지막 확인은 **10/26**, Submission 30의 4.7.1 게시다. 이번에는 설치 버전만 다시 읽었고 서버 로그인·권한은 재검증하지 않았다. 보호된 API 자격증명 파일은 없으므로 제출 전 기존 인증 포털 또는 지원되는 인증 경로의 실제 접근을 확인한다. 별도 기존 Submission 31 초안은 임의 변경하지 않는다.
- 실제 외부 계정 검증·물리 DPI·설치 앱 사용자 데이터/정상 재시작처럼 별도 미검증인 항목을 자동 테스트 통과로 대체하지 않는다. 테스트 계정 준비 또는 로그인/MFA가 필요하면 필요한 조치를 정확히 알린다.
- **11/02는 배포 작업 시작 목표이며 Microsoft 심사·Store 공개 시각을 보장하지 않는다.** 빌드, GitHub 공개, Store 제출, 심사/게시, 설치 완료를 각각 기록한다.

근거: `artifacts/maintenance/20261029-release-readiness/`의 `release-input-audit.json`, `current-runtime-inputs.json`, `release-support-inputs.json`, `public-feature-baseline.json`. 이번 확인은 입력·기존 증거 대조이며 새 빌드·테스트 전체 재실행·업로드·앱 종료를 수행하지 않았다.
