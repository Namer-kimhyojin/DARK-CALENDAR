# Google 인증 갱신 실패와 재시도 복구 — 2026-10-30

설치판 4.7.1.0의 최근 로그에서 10/30 16:50~16:51 Google 토큰 갱신 실패와
`계정을 다시 연결하세요` 안내가 반복된 것을 확인했다. 기존 로그에는 상세 실패 종류가
없으므로 최초 갱신 실패의 네트워크·서버·런타임 원인은 확정할 수 없다.

## 확인 및 수정

- 현재 저장된 암호화 토큰의 실제 Google 갱신은 정상 응답했다. 설치판 CA 인증서로도
  정상 응답했으며 개발 환경과 설치판 CA 파일의 해시가 같았다. 두 검사 모두 새 토큰은
  메모리에서만 사용했고 원래 토큰 파일의 바이트가 유지됨을 확인했다.
- 소스에서 모든 갱신 예외를 `auth_required`로 바꾸는 결함을 재현했다. 이 상태는
  통합 동기화 화면의 수동 재시도를 막고 불필요한 계정 연결로 유도한다. 대화형 경로는
  네트워크 오류 뒤에도 로그인 절차로 진입하려 했다.
- `service.py`에서 전송·시간 초과·일시적 OAuth 서버 오류는 `network_unavailable`,
  알 수 없는 오류는 `operation_failed`로 보존한다. 실제 `invalid_grant` 등 토큰 거부는
  기존 재인증을 유지하고, OAuth 클라이언트 거부는 인증 파일 오류로 구분한다.
- 설정용 `create_metadata_reader()`가 실패를 무조건 `reauth_required`로 바꾸던 경로도
  원래 실패 종류를 전달한다. 오류 응답의 자유 문구·URL·토큰은 기록하지 않는다.

분류 근거는 [google-auth 예외 계약](https://google-auth.readthedocs.io/en/latest/reference/google.auth.exceptions.html)의
`TransportError`와 `RefreshError.retryable`, Google OAuth의 구조화된 오류 코드다.

## 검증

수정 전 신규 재현 검사 23건 중 21건이 실패했다. 수정 후 잘못된 응답 유형·실제 토큰
거부·명시적 재로그인·연결 복구를 추가해 신규 28건을 포함한 **8개 파일 176건**이 통과했다.
인코딩 정책·유틸리티 **12건**, encoding guard, 변경 파일 Ruff와 `git diff --check`도 통과했다.

자동 검사는 SQLite 3.54.1 프라이빗 Python, 임시 DB·INI 설정·사용자/공유 경로와
외부 네트워크 차단 환경에서 실행했다. 근거는
`artifacts/sync-refresh-fix-20261030/results.json` 및 파일별 XML·로그다.

실제 서버 확인은 토큰 갱신까지다. 실제 일정의 전체 pull/push·삭제·설치판에서의 수정 적용은
검증하지 않았다. 사용자 DB·설정·토큰과 기존 작업은 변경하지 않았으며 제품 버전은 4.7.1을
유지한다. 변경 이력만 등록하고 빌드·배포·설치는 수행하지 않았다.
