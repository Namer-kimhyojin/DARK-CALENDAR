## 개발 실행에도 검증된 SQLite 적용

실제 `.venv` Python의 SQLite C API를 DB를 열지 않고 조회한 결과 **3.50.4**였고,
기존 WAL-reset 안전성 검사가 이를 거부했다. 수정 전 `run.bat`는 이 Python으로 `main.py`를 직접 실행했다.
공식 빌드는 별도 검증 런타임을 쓰고 있었지만 개발용 실행 경로에는 연결되지 않은 상태였다.

`run.bat`가 읽기 전용 버전 일치 검사 후 `scripts/run_development.py`를 호출하도록 수정했다.
이 진입점은 빌드와 같은 준비 모듈로 **고정된 SQLite 3.54.1 프라이빗 실행환경**을 검증하고
현재 폴더의 `main.py`와 모든 실행 인자를 전달한다. 검증·준비 실패 시 실행을 중단한다.
원래 Python·`.venv`의 DLL, 사용자의 DB·설정·계정은 바꾸지 않는다.

현재 프라이빗 환경은 기존 캐시를 재사용해 C API 버전·소스 ID·SHA256·네이티브 확장 로딩·
가상 WAL 100행 검사를 통과했다. 한글·공백이 있는 경로와 인자로 가상 `main.py`에 위임한 검사에서도
**SQLite 3.54.1·원래 인자·프로젝트 작업 폴더**를 확인했다. 실제 사용자 앱은 실행·종료하지 않았다.
