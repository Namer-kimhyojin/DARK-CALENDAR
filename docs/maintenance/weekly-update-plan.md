**Store 제출 31은 4.8.0 심사 접수 완료·인증 중, 설치는 4.7.1.0**이다. ID는 `1152921505702187447`이며 검증된 동일 MSIXUPLOAD를 사용했다. 로그인 후 모든 섹션이 변경 없는 4.7.1 기준 초안임을 확인하고 원본 백업 후 재사용했다. 18개 언어 변경 안내와 한국어·영어 새 이미지 4장을 저장했고 fresh export 453행 대조에서 허용한 26개 셀만 변경됐다. 가격·배포 국가·속성·연령 등급과 인증 통과 후 자동 게시 옵션을 보존했다.

기준일 2026-10-05의 1~14일은 10/05~10/18, 15일째 첫 배포 목표는 **2026-10-19 03:00 KST**이다. 이후 배포 목표는 11/02, 11/16처럼 14일 간격이다. 배포일은 다음 점검 주기의 1일차이기도 하며, 이전 주기 배포·누락 작업을 먼저 마친 후 새 주기의 당일 영역을 진행한다. 매주 금요일 배포는 폐지한다.

날짜가 지났다는 이유로 해당 영역을 건너뛰지 않는다. 실제 검증 기록이 없는 과거 예정일은 `pending`/`in_progress`로 남기고, 다음 새벽 실행에서 가장 오래된 미완료 작업부터 재개한다. 저장된 단계·변경·검증 증거에서 이어가며 완료 작업을 처음부터 반복하지 않는다. 해당 날짜 실행 자체가 없었어도 계획 날짜와 상태를 대조해 누락을 찾는다.

15일째에는 이전 주기의 미완료 영역·미검증 변경을 먼저 처리한다. 해당 주기의 모든 구현 변경과 삭제·리소스를 배포 입력에 포함한다. 실패 변경을 몰래 제외해 부분 배포하지 않는다. 검증 실패·미완료 작업·인증 차단이 있으면 배포를 `delayed`로 기록하고 다음 새벽에 이어서 처리한다. 완료 후 동일 목표 릴리스를 한 번만 배포하며 버전을 재시도마다 올리지 않는다. 관리자 승인 전 신규 기능 제안은 배포 대상 구현 변경에 포함하지 않는다.

`review_cycle`에 예정일·실행일·영역별 상태·단계·증거·시도 횟수·차단 사유를 보존하고 `next_actions`를 갱신한다. 컴퓨터/앱이 실행되지 않아 일정이 누락되거나 로그인/MFA가 필요하면 자동으로 우회할 수 없음을 기록한다. 실제로 같은 새벽에 완료할 수 없는 작업은 다음 실행에 재개하고 의미 있는 차단만 알린다. Store 심사 때문에 실제 공개일은 배포/제출 예정일보다 늦을 수 있다.
