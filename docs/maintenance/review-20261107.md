## 편집기 수정

메인 테마 연동 이후 자유 배치 편집기의 글자·배경 투명도 입력은 활성화되어 있었으나 실제 위젯에는 적용되지 않았다. 기존 꾸미기 화면의 연동 계약과 맞춰 읽기 전용으로 바꾸고, 메인 모양 설정을 따른다는 안내와 실제 배경 투명도를 표시한다. 적용·실행 취소 시 기존 레거시 투명도 설정과 메인 테마를 덮어쓰지 않는다. 글꼴·크기·굵기 및 배치 편집은 기존대로 유지한다.

변경 ID: `maintenance-20261107-editor-linked-opacity`. 개발 버전은 5.0.2를 유지하며 오늘 변경은 11/16 후보에 추가한다. 오늘 새 Store 패키지를 만들거나 제출하지 않았다.

근거 디렉터리: `artifacts/maintenance/20261107-0301/`. `final/day05-final-regressions.json`, `day06-regressions.json`의 통과한 앞 6개 파일, `native-persistent-app/day06-native-regressions.json`을 합산한다. 마지막 파일의 자동 생성된 `scope` 문구는 offscreen으로 남았으나 실제 실행은 `REVIEW_PRESETS_NATIVE=1`, Windows native 플랫폼이며 `review-evidence.json`에 이를 명시한다. 개인 QSettings 보존을 검사했고 임시 프로필을 사용했다. 실제 Store 앱의 사용자 데이터 인수를 대신하지 않는다.

## 게시·설치 후속

기존 Store Submission 33에서 5.0.2.0 게시를 확인했다. 이 PC에도 Store 서명된 5.0.2.0이 이미 설치되어 있었으며 최종 CI payload와 EXE·SQLite DLL 해시가 일치한다. 별도 Submission 34 초안은 수정하지 않았다. [배포 확인표](../release-5.0.2-checklist.md).

설치 앱 프로세스·시작 로그·자리 비움 화면을 관찰했다. UI 도구가 대상 창을 활성화하지 못해 정상 재시작·핵심 화면·사용자 데이터 비교는 후속으로 남겼다. SQLite 직접 로드 검사는 이 환경에서 확인 불가로 분리하고 일치한 DLL 해시 증거를 보존했다. 실행 앱을 강제 종료하지 않았다.

홈페이지 Store 심사 대기 표시를 게시 상태로 바꿨다. 첫 Pages 배포의 서버 오류는 같은 run 재시도로 해소했다. Quality Gate에서 발견한 5.0.2 배포 점검 문서 누락을 근거 있는 확인표로 보완했다. 실제 공개 파일과 후속 CI 상태는 `homepage-publication-verification.json`에 기록한다. 홈페이지 요청은 전체 수집 0건이며 외부 답변·상태 변경은 하지 않았다.
