# Dark Calendar 다이얼로그 시인성·편의성 감사

## 감사 기준

- 정보 위계: 제목, 설명, 핵심 입력, 주 행동의 순서가 한 번에 파악되는가
- 시인성: 100~150% 배율과 작은 화면에서 내용·푸터가 잘리지 않는가
- 조작 편의: 자주 쓰는 버튼은 충분히 크고 기본·취소 동작이 예측 가능한가
- 접근성: 창·입력·아이콘 버튼에 읽을 수 있는 이름과 상태가 있는가
- 일관성: 공통 다이얼로그 토큰, 포커스 표시, 버튼 순서를 공유하는가
- 오류 예방: 위험 행동과 보조 행동이 시각적으로 구분되고 키보드로 완료 가능한가

## 구현 우선순위

1. 완료: 공통 화면 맞춤, 접근성 이름, 폼 라벨 연결, 44px 푸터 버튼
2. 완료: Google 캘린더 설정, 도움말 센터, 자리 비움 설정, 체크리스트 하위 창
3. 검증: 자동 회귀 테스트, 인코딩 정책, 집중 다이얼로그 테스트
4. 수동 확인 필요: 실제 Windows 125/150% 배율, NVDA 낭독, Google 인증, 프린터 드라이버

## 완료 기준

- 작은 화면에서 창과 하단 행동이 작업 영역을 벗어나지 않는다.
- 기본 행동은 Enter, 취소는 Esc로 예측 가능하게 동작한다.
- 텍스트가 없는 아이콘 버튼도 의미가 낭독된다.
- 폼 라벨이 해당 입력칸의 접근성 이름과 키보드 포커스 연결을 제공한다.
- 주요 푸터 버튼은 44px 이상, 반복 행의 아이콘 행동은 40px 이상이다.
- 수정한 Python 파일은 인코딩 가드와 정적 검사를 통과한다.

## 검증 결과 (2026-08-06)

- 실제 Windows 렌더링: 도움말 1080×720, 자리 비움 900×720, Google 설정 980×680, 체크리스트 항목 편집 560×520
- 정적 검사: 수정 Python 파일 전체 통과
- 다이얼로그 회귀: 신규·편집기 31건, 주요 화면 57건, 인쇄 미리보기 3건을 프로세스 분리하여 총 91건 통과
- 인코딩: 컴파일, 정책 테스트, 유틸리티 테스트를 포함한 인코딩 가드 통과
- 인쇄 미리보기는 Windows Qt 네이티브 위젯의 프로세스 누적 상태 영향을 피하기 위해 별도 프로세스로 검증
