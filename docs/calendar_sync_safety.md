# 다중 서비스 동기화 안전 계약

서비스 연결은 해당 서비스 캘린더와 로컬 일정 사이에서만 수행한다. 같은 제목과 시간이더라도 Google, Outlook, iCloud, 네이버 간 자동 복사나 병합은 하지 않는다.

| 상황 | 처리 | 현재 검증 범위 |
|---|---|---|
| 다른 서비스·계정에서 동일한 원격 ID 사용 | 계정/원격 캘린더를 해시한 로컬 캘린더 키로 구분. 삭제 대기는 `(calendar_id, event_id)` 복합 키 | 공통 엔진 회귀 테스트 |
| 기존 삭제 대기 메타데이터 | 복합 키로 마이그레이션하며 ETag, 재시도 횟수, 오류 보존 | 마이그레이션 및 재실행 테스트 |
| 다른 계정의 삭제 대기가 동일 ID 조회에 영향 | 조회·삭제·실패 기록을 해당 캘린더로 한정 | 계정 간 조회·삭제 격리 테스트 |
| 로컬과 원격을 동시에 변경 | 양쪽 내용을 충돌 기록에 보존. 자동 덮어쓰기 보류 | 공통 엔진 회귀 테스트 |
| HTTP 요청 중 로컬 수정·삭제 | 다시 조회해 수정 보존. 생성 후 로컬 삭제는 원격 삭제 대기에 기록 | 공통 엔진 회귀 테스트 |
| 생성 성공 후 응답 유실 | 저장된 트랜잭션 ID로 다음 조회에서 생성 결과 연결 | 공통 엔진 회귀 테스트 |
| 원격 삭제 | 로컬 일정 보존 및 원격 삭제 상태 기록. 자동 재생성 보류 | 공통 엔진 회귀 테스트 |
| 삭제 전에 원격 내용 변경 | ETag 불일치는 삭제 충돌로 기록 | 공통 엔진 회귀 테스트 |
| 인증/권한 실패, 호출 제한, 서버 장애 | 401/403/429/5xx 발생 시 이후 쓰기·삭제 중단. 삭제 대기 보존 | 쓰기 및 삭제 중단 테스트 |
| 캘린더 이동 | 원래 연결을 다른 서비스 대상으로 재사용하지 않고 이동 오류 기록 | 공통 엔진 회귀 테스트 |
| 원격 조회·변환 중 로컬 캘린더 이동/선택 해제 | 쓰기 잠금 안에서 내용·캘린더·연결 스냅샷·활성 선택 재확인. 이전 캘린더로 전송/덮어쓰기 보류 | 경합 재현 테스트 |
| 캘린더 이동 오류 복구 | 원래 캘린더로 되돌아와 로컬/원격이 일치하면 오래된 오류 제거 | 복구 재현 테스트 |
| 종료 직전 결과·오류 도착 | 계정/자동 설정/오류 상태 갱신 중단 | 서비스별 종료 테스트 |
| 설정 저장·계정 전환의 DB 실패 | Qt 콜백 밖으로 예외를 전파하지 않고 오류 표시. 저장 실패 시 선택 보존 | 설정 클릭·계정 전환 실패 테스트 |
| 여러 캘린더 중 후속 실패 | 먼저 반영된 캘린더의 일정도 화면에 다시 표시. 전체 성공으로 표시하지 않음 | 서비스별 부분 실패 테스트 |
| 읽기 전용 캘린더 | 생성·수정·삭제 요청 제한 | 공통 엔진 회귀 테스트 |

## CalDAV 구현과 추가 검증

아래 항목은 실제 CalDAV 어댑터를 모의 서버 응답 및 임시 DB/설정으로 검증했다. 실제 사용자 계정 로그인과 원격 저장 검증은 별도다.

- 서버 탐색과 리다이렉트의 HTTPS/서비스 호스트 검증. 허용되지 않은 호스트에는 인증정보 전달 금지.
- REPORT의 전체 응답 검증 후 반영. 일부 성공·일부 실패 응답, 잘못된 XML/ICS, 시간 초과는 불완전한 조회로 처리.
- iCloud 앱 전용 암호와 네이버 인증 조건을 분리. 암호는 Windows 사용자 범위에서 암호화 저장.
- 반복 일정, 제외 날짜, 수정된 회차, 시간대 및 종일 일정의 종료일 변환 검증.
- 반복 회차 편집·삭제는 지원 여부를 명시. 한 회차 삭제가 시리즈 파일 전체 삭제로 이어지지 않도록 차단.
- PUT/DELETE의 ETag 조건 필수. 생성은 고정 UID와 `If-None-Match`로 재시도 중복 방지.
- 네이버는 공식 지원 제한을 고려해 기본 읽기 전용. 실제 연결 검증 없이 양방향 지원을 표시하지 않음.
- 동일 계정의 중복 워커 실행 차단 및 종료 시 네트워크 작업의 협력적 중단.
- 전체 ETag 목록 조회 후 변경 본문만 다운로드. 계정·캘린더별 SQLite 캐시를 재시작 후 재사용하며 잘못된 캐시는 다시 내려받음. 부분 multiget·ETag 경합·취소·저장 실패 시 이전 캐시 보존.
- 다운로드 본문 합계 8 MiB, 리소스 및 확장 회차 각각 10,000개 제한. multiget은 50개씩 요청하며 405/501이면 전체 본문 조회로 복귀.
- UID·반복 회차를 기존 연결/삭제 대기에 ALTER TABLE로 추가. 같은 캘린더의 유일한 UID·회차와 이전 주소 404를 확인해야 주소를 바꿈. 충돌 기준과 로컬 ID, 삭제 조건 ETag를 보존.
- URL 재사용 시 다른 UID는 수정·삭제 보류. 생성 요청 중 로컬 삭제 및 주소 검사 중 로컬 삭제도 UID를 가진 삭제 대기를 유지하여 일정이 다시 생기지 않도록 처리.

위 프로토콜은 [RFC 4791](https://www.rfc-editor.org/rfc/rfc4791.html)의 calendar-query, calendar-multiget 및 캘린더 안의 UID 식별 규칙을 사용한다. RFC 6578의 sync-token 변경 목록 조회는 아직 구현하지 않았다. UID를 아직 저장하지 않은 오래된 연결은 주소가 바뀌기 전 정상 동기화가 한 번 필요하다.

실제 계정의 인증, 원격 저장, 재시작 후 복구는 로컬 모의 테스트와 별도로 확인한다.

공통 엔진은 계정별 실행 잠금, SQLite 쓰기 잠금 후 스냅샷 재확인, 선택 저장의 원자성을 적용한다. 서버가 기본 종료 시각 등을 채워 주면 동시 로컬 수정이 없는 경우에만 정규화 값을 저장하여 반복 전송을 막는다. ETag만 달라지고 표시 내용이 같으면 내용 충돌로 처리하지 않는다. 서버에서 캘린더 이름이 바뀌어도 사용자가 지정한 로컬 이름은 보존한다.

조회 전용 일정 삭제와 삭제 충돌은 자동 재시도를 멈추고 수동 확인을 기다린다. 신규 생성 요청 중 404가 발생하면 캘린더 접근 상실로 분류하며 아직 생성하지 않은 일정을 원격 삭제 상태로 표시하지 않는다.

## ICS 구독 스냅샷

전체 피드를 검증한 후 해당 구독의 읽기 전용 사본만 한 트랜잭션으로 반영한다. UID 누락·중복, 잘못된 날짜·종료 범위, 잘린 피드, DB 오류가 있으면 이전 스냅샷과 마지막 성공 시각을 보존한다. 유효한 빈 VCALENDAR는 기존 사본을 제거하며 로컬 일정과 다른 구독은 유지한다. 저장 중 취소도 롤백한다. 외부에서 구독을 비활성화하거나 주소를 바꾸면 이전 주소의 응답을 반영하지 않는다.

반복 일정은 UID와 원래 회차 시각으로 구분하여 변경된 회차가 전체 시리즈를 덮어쓰지 않게 한다. 반복 회차 조회 범위는 공통 엔진과 같은 과거 120일~미래 400일이며, 단일 일정에는 이 범위 제한을 적용하지 않는다. 피드는 8 MiB, 전체 일정/확장 회차는 10,000개로 제한하고 밀집 반복을 확장 전에 거부한다. 서비스가 제공하는 피드의 완전성은 서버 계약에 의존한다. 정상 형식의 유효한 빈 피드는 서버의 삭제 결과로 취급한다.

삭제 재시도와 충돌의 '내 변경' 선택은 해당 서비스에서 즉시 동기화한다. ETag와 읽기 전용 제한은 재시도에도 유지한다. 실제 계정 및 패키징 검증 상태는 [2026-10-05 오류 점검](ux-audit/calendar-sync-exceptions-2026-10-05.md)에 별도로 기록한다.
