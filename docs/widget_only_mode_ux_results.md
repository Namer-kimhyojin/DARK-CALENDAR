# 위젯 전용 모드 UI/UX 개선 결과

> 계획: [widget_only_mode_ux_plan.md](widget_only_mode_ux_plan.md)

## 반영 내용

- 달력 버튼을 `달력 접기` / `달력 펼치기`로 바꾸고 체크 상태·접근성 이름을 일치시켰습니다. 넓은 창은 메인 복귀·고정·꾸미기의 라벨을 표시하고, 좁은 창은 아이콘과 접근성 이름을 유지합니다. 필터·추가·달력 조작의 의미 라벨은 유지합니다.
- 더 보기 메뉴를 날짜 이동 / 업무 관리 / 보기 설정 / 창 관리로 나누고, 꾸미기와 메뉴에서 `배치` 명칭을 통일했습니다. 항목 메뉴는 키보드 메뉴 키와 Shift+F10으로도 열립니다.
- 동일 날짜·필터에서 목록 갱신 시 읽던 항목과 화면 내 위치, 완료 체크·제목 등 조작 포커스를 복원합니다. 항목 삭제 시 다음 항목, 없으면 이전 항목으로 이어집니다. 새 날짜·필터에서는 목록 처음으로 이동하며, 지연 복원 전에 사용자가 다른 조작부로 옮긴 포커스를 빼앗지 않습니다.
- 완료·실패·실행 취소 결과에 항목명을 표시합니다. 실행 취소 버튼에 포커스가 있으면 자동 만료를 미룹니다. 저장 실패 시 체크 상태를 원복하고, 실행 취소 실패 시 재시도할 수 있습니다. 처리 결과를 항목명보다 먼저 표시합니다. 긴 피드백은 두 줄 높이로 제한하고 전체 문장은 도움말·접근성 이름으로 제공합니다.
- standard/comfortable 밀도는 긴 제목을 두 줄, compact는 한 줄로 읽습니다. 제목·시간·빠른 메뉴의 겹침을 보완했습니다. 필터가 비었지만 다른 유형에 항목이 있는 경우 그 차이를 설명하며 개수·선택 날짜·완료 포함 상태를 접근성 설명에 함께 제공합니다.
- 꾸미기에 초안 적용 경계와 배치별 달력 표시 설명을 추가했습니다. 콤보·스핀·슬라이더 및 내부 입력부의 휠은 값을 바꾸지 않고 설정 화면을 스크롤합니다. 키보드·클릭 조정은 유지합니다. 배치 카드 크기는 번역 라벨과 글꼴 폭에 맞추며 전체 배치를 펼친 뒤 선택 카드로 포커스를 돌립니다.
- 항목 내용·스타일이 같은 행을 재사용합니다. 식별자가 없거나 중복된 행은 합쳐지지 않도록 재사용을 제한했습니다. 새 문구 16개는 번들 19개 언어에 반영했습니다.

## 검증

- 관련 위젯 테스트 10개 파일: 파일별 독립 프로세스에서 164개 통과. 신규 회귀는 core 26개, 꾸미기 24개입니다.
- 번역 구조·정규 형식 검사 15개, 인코딩 테스트 12개 통과. 인코딩 가드, 수정 Python 파일 Ruff, Git 공백 검사 통과.
- 여러 Qt 테스트 파일을 한 프로세스에서 실행한 시도는 중간에 요약 없이 종료 코드 1로 끝났습니다. 파일별 실행은 모두 통과했으므로 합쳐진 실행 또는 전체 pytest 성공으로 기록하지 않습니다.
- Windows Qt에서 배율 100%, 125%, 150%, 200%를 별도 프로세스로 확인했습니다. 배율은 QT_SCALE_FACTOR 시뮬레이션이며 물리 모니터 이동 검증과 구분합니다.
- 각 배율에서 25개 관찰·화면 캡처를 남겼고 제목/시간/메뉴 겹침, 달력·필터 문구 잘림, 가로 스크롤, 꾸미기 카드 겹침은 0건입니다.
- 각 배율에서 크기·기본 배치·밀도·라이트/다크/샘플 사용자 스킨·읽기 전용/완료/긴 제목/빈 목록/로딩/지연·6개 언어 화면·꾸미기 적용 전 취소를 확인했습니다. 모든 조합의 전수 검증은 아닙니다.

|---|---|---|

테스트용 메모리 설정·합성 데이터를 사용했으며 사용자 DB·Google 동기화·실제 앱 설정을 변경하지 않았습니다. 수치와 상세 판정은 [100% 관측 JSON](../artifacts/widget-mode-ux-improvement-20261001/final-scale-1/observations.json) 및 [검증 스크립트](../scripts/validate_widget_mode_ux_plan.py)를 참조합니다.

## 성능 측정

Windows 11, Python 3.13.15, PyQt 6.10.2 / Qt 6.10.0, 100% 배율, 420×520·기본 라이트·stacked·standard에서 조건별 10회 측정했습니다. DB 조회·파일 읽기 비용은 제외하고 Qt 이벤트·배치 처리는 포함합니다.

| 100개 항목 조건 | p95 |
|---|---|
| 첫 항목 제목만 변경하고 나머지는 그대로 유지 | 16.83ms |
| 동일 데이터 갱신 | 0.62ms |
| 전체 → 업무 필터 | 12.60ms |
| 빈 창의 최초 목록 생성 | 163.56ms |

부분 갱신·필터는 계획의 100ms 목표를 충족합니다. 최초 생성이나 모든 행이 바뀌는 갱신을 100ms 이내로 보장하지 않습니다. 300개 항목 최초 생성은 p95 787.46ms입니다. 대량 목록의 최초 생성 개선은 후속 성능 과제로 남깁니다. 중간 측정의 부분 갱신 204ms에서 개선됐으나 중간 구현과 최종 구현의 비교이며 기존 배포본 대비 성능 수치로 사용하지 않습니다.
