개인정보처리방침

시행일: 2026년 10월 5일

Air Calendar(이하 "본 앱")는 Zinz-Soft(이하 "개발자")가 개발·배포하는 Windows용 데스크톱 캘린더 애플리케이션입니다. 본 방침은 본 앱이 이용자의 정보를 어떻게 처리하는지 설명합니다.

1. 핵심 요약

  • 개발자는 이용자의 개인정보를 수집하지 않습니다. 본 앱에는 서버, 계정 시스템, 분석 도구, 광고가 없습니다.
  • 이용자가 만든 모든 일정·업무·설정 데이터는 이용자 PC에 저장됩니다. 사용자가 외부 캘린더 연동을 켜면 선택한 일정은 해당 서비스와도 동기화됩니다.
  • 외부 전송은 이용자가 직접 활성화한 기능(Google·Outlook·iCloud·네이버 캘린더 연동, 날씨 위젯, ICS 구독)에 한해, 해당 서비스 제공자에게만 이루어집니다.

2. 로컬에 저장되는 데이터

본 앱은 다음 데이터를 이용자 PC의 로컬 폴더(%LOCALAPPDATA%\kimhyojin\Dark Calendar)에 저장합니다.

데이터용도
일정·업무·체크리스트 데이터 (SQLite DB)캘린더 기능 제공

Outlook 인증 캐시, CalDAV 인증 파일 — 해당 서비스 연결 시현재 Windows 사용자 계정의 DPAPI로 암호화한 인증 정보
선택 캘린더의 일정 캐시·연결 기록·충돌 및 삭제 대기 기록서비스별 동기화, 변경 비교와 안전한 재시도
진단 로그 파일오류 확인

이 데이터는 개발자에게 전송되지 않으며, 개발자는 접근할 수 없습니다.

3. 제3자 서비스로의 전송 (이용자가 활성화한 경우에만)

3.1 Google Calendar 연동

  • 이용자가 Google 계정으로 로그인하면 본 앱은 Google Calendar API를 통해 일정 데이터를 읽고 씁니다.
  • 전송 대상: Google LLC (Google 개인정보처리방침)
  • 인증 토큰은 이용자 PC에만 Windows DPAPI로 암호화되어 저장되며, 개발자 서버로 전송되지 않습니다.
  • 연동 해제 시 본 앱은 Google에 토큰 취소(revoke)를 요청하고 로컬 토큰을 삭제합니다.
  • 본 앱의 Google API로부터 받은 정보의 사용은 제한적 사용(Limited Use) 요구사항을 포함한 Google API 서비스 사용자 데이터 정책을 준수합니다.

3.2 날씨 위젯

  • 이용자가 입력한 도시 이름은 앱에 포함된 GeoNames 도시 데이터에서 로컬로 검색되며 외부로 전송되지 않습니다.
  • 검색된 위도·경도(소수점 4자리)와 일반적인 웹 요청 정보(IP 주소 등)는 날씨 조회를 위해 노르웨이 기상청 MET Norway(api.met.no)에 전달될 수 있습니다. MET Norway는 API 접근 로그를 노르웨이 오슬로의 자체 데이터센터에 저장합니다.
  • 날씨 데이터는 MET Norway의 CC BY 4.0/NLOD 2.0 데이터이며, 도시 데이터는 GeoNames의 CC BY 4.0 데이터입니다.
  • GPS 등 기기 위치정보는 수집·사용하지 않습니다.

3.3 ICS 캘린더 구독

  • 이용자가 직접 입력한 ICS 주소(URL)에 접속하여 일정을 가져옵니다. 해당 URL의 운영자에게 일반적인 웹 요청 정보(IP 주소 등)가 전달될 수 있습니다.

3.4 Outlook · Microsoft 365

  • 이용자가 로그인하고 권한을 승인하면 Microsoft Graph를 통해 선택한 캘린더의 일정과 기본 계정 정보를 조회하고 쓰기 가능한 일정을 수정합니다. 사용 권한은 Calendars.ReadWrite와 User.Read입니다.
  • 인증 캐시는 현재 Windows 사용자의 DPAPI로 암호화해 PC에 저장합니다. 연결 해제는 로컬 인증 캐시를 지우고 해당 연결을 비활성화합니다. 서버의 앱 접근 권한 철회는 Microsoft 계정·조직의 앱 관리 화면에서 별도로 수행합니다.

3.5 iCloud · 네이버 CalDAV

  • 이용자가 입력한 계정·인증 암호와 캘린더 요청은 선택한 Apple 또는 네이버 서비스에 직접 전달됩니다. iCloud는 앱 전용 암호를 사용합니다. 네이버는 읽기 전용이며 연결 가능 여부는 서비스 정책에 따릅니다.
  • 인증 정보는 현재 Windows 사용자의 DPAPI로 암호화한 별도 파일에 저장합니다. 설정 레지스트리에 암호를 평문으로 저장하지 않습니다. 일정 본문·ETag·연결 기록은 로컬 동기화 캐시에 보관됩니다.
  • 연결 해제는 해당 로컬 인증 파일을 삭제하고 캘린더를 비활성화하며 원격 원본을 삭제하지 않습니다. 서비스 계정의 앱 전용 암호도 필요하면 해당 서비스에서 별도로 취소할 수 있습니다.

4. 데이터 보관 및 삭제

  • 모든 데이터는 이용자가 삭제할 때까지 로컬에 보관됩니다.
  • Google 연동 해제: 앱 내 Google Calendar 설정에서 연동 해제 시 토큰이 취소·삭제됩니다. Google 계정 보안 설정에서도 언제든 접근 권한을 철회할 수 있습니다.
  • 전체 삭제: 앱 제거 후 %LOCALAPPDATA%\kimhyojin\Dark Calendar 폴더를 삭제하면 모든 데이터가 완전히 제거됩니다.

5. 아동의 개인정보

본 앱은 개인정보를 수집하지 않으므로 아동으로부터 별도의 정보를 수집하지 않습니다.

Privacy Policy

Effective date: October 5, 2026

Air Calendar ("the App") is a Windows desktop calendar application developed and distributed by Zinz-Soft ("the Developer"). This policy explains how the App handles your information.

1. Summary

  • The Developer does not collect any personal data. The App has no server, no account system, no analytics, and no advertising.
  • All schedules, tasks, and settings you create are stored on your PC. Enabling calendar sync also exchanges selected events with the chosen provider.
  • Data leaves your device only through features you explicitly enable (Google, Outlook, iCloud and Naver calendar connections, weather and ICS subscriptions), and only to those service providers.

2. Data stored locally

The App stores the following on your PC under %LOCALAPPDATA%\kimhyojin\Dark Calendar:

DataPurpose
Schedule/task/checklist data (SQLite database)Core calendar features
App settings (Windows registry HKCU\Software\kimhyojin\Dark Calendar)Preserving theme, language, layout
Google auth token (token.json, stored encrypted) — only if Google sync is enabledKeeping sync signed in
Outlook authentication cache and CalDAV credential files — when connectedAuthentication protected with Windows DPAPI for the current user
Selected calendar event caches, link records, conflicts and deletion queuesProvider-specific sync, change comparison and safe retries
Diagnostic log filesTroubleshooting

This data is never transmitted to the Developer, and the Developer has no access to it.

3. Transfers to third-party services (only when you enable them)

3.1 Google Calendar sync

  • When you sign in with your Google account, the App reads and writes your calendar events via the Google Calendar API.
  • Recipient: Google LLC (Google Privacy Policy)
  • Auth tokens are stored only on your PC, encrypted with Windows DPAPI, and never sent to the Developer.
  • When you disconnect, the App requests token revocation from Google and deletes the local token.
  • The App's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

3.2 Weather widget

  • The city name you type is searched locally in the GeoNames city dataset bundled with the App and is not sent externally.
  • The resulting latitude and longitude (rounded to four decimal places), together with standard web request information such as your IP address, may be sent to MET Norway (api.met.no) to retrieve weather data. MET Norway stores API access logs in its own data center in Oslo, Norway.
  • Weather data is provided under MET Norway's CC BY 4.0/NLOD 2.0 terms, and city data is provided by GeoNames under CC BY 4.0.
  • Device location (GPS, etc.) is never collected or used.

3.3 ICS calendar subscriptions

  • The App fetches events from ICS URLs you enter yourself. Standard web request information (such as your IP address) may be visible to the operator of that URL.

3.4 Outlook and Microsoft 365

  • After sign-in and consent, Microsoft Graph reads selected calendar events and basic account details and updates writable events using Calendars.ReadWrite and User.Read.
  • The authentication cache is encrypted with Windows DPAPI for the current user. Disconnecting deletes the local cache and deactivates this connection. Revoke server-side app access separately in your Microsoft account or organization's app management.

3.5 iCloud and Naver CalDAV

  • Your account, authentication password and calendar requests are sent directly to the selected Apple or Naver service. iCloud uses an app-specific password. Naver is read-only and availability depends on its service policy.
  • Credentials are stored in separate files encrypted with Windows DPAPI for the current user, not as plaintext registry settings. Event bodies, ETags and link records are retained in the local sync cache.
  • Disconnecting removes the local credential file and deactivates calendars without deleting remote events. You may also revoke app-specific passwords with the provider.

4. Retention and deletion

  • All data remains on your PC until you delete it.
  • Disconnecting Google sync: revokes and deletes the token. You can also revoke access anytime at Google Account permissions.
  • Full deletion: uninstall the App, then delete the %LOCALAPPDATA%\kimhyojin\Dark Calendar folder to remove all data.

5. Children's privacy

The App collects no personal data and therefore collects no data from children.

6. Changes to this policy

If this policy changes, the updated version and effective date will be posted on this page.

  • 수정·삭제 비밀번호는 소금값과 서버 비밀값을 사용하는 단방향 해시로 저장하며, 원문을 저장하거나 게시판에 공개하지 않습니다. 비밀번호는 복구할 수 없습니다.
  • 작성자는 등록한 비밀번호로 자신의 글을 수정·삭제할 수 있습니다. 관리자는 처리 상태·답변 관리와 게시글 삭제가 가능합니다.
  • 이미지는 글당 최대 3장, 장당 5MB까지 첨부할 수 있습니다. 이미지 안의 개인 일정·연락처 등 공개를 원하지 않는 내용을 직접 가린 뒤 첨부하세요. 게시글 수정 시 이미지 추가·제거가 가능하며, 게시글 삭제 시 연결된 이미지도 정리됩니다. 일시적인 파일 저장소 장애가 있으면 삭제된 이미지는 즉시 열람을 차단하고 후속 요청에서 파일 정리를 재시도합니다.
  • 과도한 요청을 제한하기 위해 서버가 접속 IP의 비밀값 기반 해시와 요청 횟수를 저장합니다. 원문 IP를 게시판 DB에 저장하지 않습니다. 제한 정보는 만료 후 후속 요청에서 정리되며, 만료된 관리자 세션도 후속 로그인에서 정리됩니다. 관리자 세션은 1시간 동안 유효합니다.
  • 게시글은 삭제할 때까지 유지됩니다. 본문에 개인 일정·연락처·인증 키 등 공개를 원하지 않는 정보를 넣지 마세요. 삭제 관련 문의는 위 연락처로 할 수 있습니다.
  • 홈페이지와 게시판 서버에 접속할 때 호스팅 제공자는 IP 주소 등 일반적인 웹 요청 정보를 처리할 수 있습니다.

Website request board

Board notice added: October 1, 2026

Separate from the desktop App, this public board stores and displays the nickname, title, content, request type, optional app version and environment, and timestamps you submit. Images you attach are stored on the server and displayed publicly with the post. Status updates and developer replies are public. It does not automatically retrieve your calendar or settings.

You may attach up to three PNG, JPG or WebP images, 5MB each. Remove private details from images before attaching them. Authors can add or remove images when editing. Deleting a post also removes its attachments. During a temporary storage outage, access to deleted attachments is blocked immediately and file cleanup is retried on subsequent requests.

Edit/delete passwords are stored as salted, server-peppered one-way hashes, never as plaintext. They cannot be recovered. Authors can edit or delete with their password; the administrator can manage status and replies or delete posts. Posts remain until deleted.

To limit excessive requests, the board database stores secret-based IP hashes and request counts, not raw IP addresses. Expired rate-limit records are removed on subsequent requests; expired admin sessions are removed on subsequent logins. Admin sessions last one hour. Hosting providers may process standard connection information, including IP addresses. Do not post private information. Use the contact above for deletion inquiries.
