| 번역 구조 검사 실패 | 17개 언어의 기존 날씨 키 9개, 총 153개 번역 보완. 새 식별자 경고는 19개 언어에 추가 | 전체 로케일 구조·자리표시자 및 동기화 키 검사 |

UID·회차는 기존 연결 및 삭제 대기 테이블에 `ALTER TABLE`로 추가한다. 기존 일정·대기 ETag·재시도 정보는 보존한다. UID가 아직 없는 이전 연결은 정상 동기화에서 식별자를 기록한 뒤부터 주소 변경을 복구할 수 있다. 이미 주소가 바뀐 오래된 연결은 자동으로 추정·병합하지 않는다.

프로토콜은 [RFC 4791](https://www.rfc-editor.org/rfc/rfc4791.html)의 calendar-query/calendar-multiget 및 컬렉션 안의 UID 규칙을 사용한다. 현재 개선은 **ETag 기반 변경 본문 다운로드**다. 전체 목록 자체의 조회를 줄이는 RFC 6578 sync-token 방식은 아직 구현하지 않았다.

## 이전 테스트 격리 오류 정정

이전 `sync-integration`/`sync-exceptions` 앱 실행 스크립트는 기본 포맷/경로만 바꾸고 `QSettings("kimhyojin", "Dark Calendar")`를 사용했다. Windows에서 이 생성자는 네이티브 저장소를 사용하므로 설정 격리가 되지 않았다. 이전 앱 실행의 설정 격리 주장은 이 후속 기록으로 정정한다. 임시 DB 사용 및 기존 개별 테스트 결과와 구분한다.

실제 설정에 남은 알려진 `caldav::icloud::smoke-fixture` 값만 정확히 비교해 제거했다. 해당 계정의 암호화 인증 파일은 없었다. 이전 스크립트는 `gcal_enabled=false`, `language=ko`, `text_theme=dark`도 썼다. 사전 원본이 없어 이 값들을 임의로 복원하지 않고 현재 설정을 유지했다.

기존 두 앱 실행 스크립트는 안전한 새 스크립트를 호출하도록 바꿨다. 새 앱/회귀 실행은 모든 일반 QSettings 생성자를 임시 INI로 명시적으로 전환하고 LOCALAPPDATA/APPDATA/PUBLIC도 격리한다. 실제 설정 스냅샷은 메모리에서만 비교하며 계정·개인 설정 값을 증거 파일에 출력하지 않는다. 앱 실행의 예외 경로에도 워커 종료를 등록했다.
