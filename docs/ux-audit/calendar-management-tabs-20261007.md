# 캘린더 관리 탭 개편 — 2026-10-07

사용자 요청에 따라 로컬 캘린더 관리와 ICS 구독 추가를 각각 전용 탭으로 분리했다. 내 캘린더의 추가 버튼 둘을 제거하고, 같은 캘린더를 관리할 때 전용 탭의 해당 항목으로 이동한다. 등록·저장·동기화 로직은 기존 경로를 재사용한다.

## 사용자 흐름

- 연결 및 구독: 계정 연결과 서비스별 상태·자동 동기화 설정. ICS 관리 진입도 전용 구독 탭을 연다.
- 내 캘린더: 전체 목록의 표시 여부와 ‘기본 저장’ 선택. 로컬·ICS 상세의 관리 버튼은 전용 탭의 같은 항목을 연다.
- 로컬 캘린더: 로컬 목록만 표시하고 추가·이름·색상·표시·기본 저장·제거를 제공한다. 추가한 항목을 바로 선택한다.
- ICS 구독: 구독 목록만 표시하고 추가·주소 수정·표시·개별 갱신·갱신 중지·구독 해제를 제공한다. 읽기 전용 제약과 비공개 주소 보호를 유지한다.
- 문제 해결: 실패 구독의 해결 버튼은 ICS 탭에서 정확한 항목을 선택하고 주소 노출을 초기화한다.

기존 `services`·`calendars`·`issues` 문자열 진입과 Google 전용 `initial_tab="calendar"`는 유지했다. 새 `local`·`ics` 진입을 지원하며 내부 숫자 인덱스 대신 위젯으로 이동한다. 문제 해결은 마지막 탭에 배치하고 640px에서도 한국어 다섯 탭과 문제 개수가 잘리지 않도록 탭 너비를 조정했다.

## 변경과 데이터 보호

`CalendarManagerPage`의 범위별 인스턴스를 재사용한다. 고정 유형 필터는 사용자 검색과 서비스 콤보에서 독립되어 다른 유형이 섞이지 않는다. 세 페이지는 같은 coordinator의 목록과 저장 정책을 사용하며 기본값·표시 변경을 함께 반영한다.

기존 로컬·ICS 저장, 주소 정규화·중복 거부, 작업 중 추가·주소 수정·삭제 차단, 읽기 전용 기본값 차단을 유지했다. DB 스키마·계정 인증·실제 일정 소속·동기화 엔진은 이번 변경으로 수정하지 않았다. 내 캘린더 개요에서는 로컬·ICS의 중복 상세 관리 작업을 전용 탭 링크로 바꿨다.

새 안내 6개를 19개 번들에 추가했다. 한국어·영어와 나머지 17개 언어의 영어 대체 문자열이다.

## 검증

중복 제외 **245개 통과**: 기능·회귀·로케일 233개와 인코딩 정책·유틸리티 12개다. 신규 전용 탭 검사 15개를 포함하며 미해결 실패·오류·건너뛴 검사는 없다. 전체 저장소 테스트 통과를 뜻하지 않는다.

처음에는 기존 3탭·내 캘린더의 ICS 관리 동작을 전제로 한 검사 3개가 실패했다. 새 전용 탭 경로로 기대를 바꾸고 재검증했다. Google 설정 조회 실패 검사 1개는 이전 오류 안내 개선의 안전한 `database_failed` 코드로 기대를 맞췄다. ICS 로컬 HTTP 검사 1개는 샌드박스의 네트워크 접근에 실패하여, 승인된 격리 실행에서 127.0.0.1 테스트 서버·임시 DB·설정만 사용해 통과했다. 실제 계정이나 외부 feed를 조회하지 않았다. 최초 결과도 원본 XML에 남겼다.

Windows 네이티브 Qt 한국어 밝음·어두움, 실제 100%·150% 배율, 640·1040px에서 최종 캡처 **36개**, 조건 **168개**를 확인했다. 실제 추가·이름 변경·기본 저장·표시·갱신 클릭, 개요 관리 링크와 실패 구독 이동, 작은 창 스크롤과 탭 문구를 검증했다. Qt·geometry·Python 콜백 오류는 0건이고 개인 QSettings를 보존했다. 격리 환경의 선택적 QtAwesome codicon 폰트 안내는 요청 아이콘 렌더링에 영향을 주지 않았다.

제품 3개·관련 테스트 5개 파일의 범위 Ruff와 Python 컴파일, 인코딩 검사, diff 검사를 완료했다. [집계·현재 소스 해시](../../artifacts/calendar-management-tabs-20261007/summary.json), [네이티브 화면 결과](../../artifacts/calendar-management-tabs-20261007/qa/native-summary.json)에 기록했다.

격리된 임시 경로로 `run_encoding_guard.py`도 통과했다. 전체 컴파일에서 기존 pytest 임시 디렉터리 2개를 열 수 없다는 안내가 있었으며, 수정 제품·테스트 파일은 별도 컴파일로 확인했다. 반복된 인코딩 검사 12개는 위 집계에서 한 번만 계산했다.
