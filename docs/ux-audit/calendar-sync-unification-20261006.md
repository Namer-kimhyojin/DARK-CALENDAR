# 캘린더 동기화 단일화 및 안정성 점검 — 2026-10-06

소스 수정과 로컬 검증을 완료했다. 스토어 설치본을 교체하거나 새 패키지를 제출하지 않았다.

## 사용자 흐름

- 상단 동기화 아이콘: 통합 동기화 허브를 연다. 전체 실행·계정 설정·문제 확인은 허브에서 처리한다.
- 상단은 작은 단일 버튼과 중립 색상의 보조 상태 문구를 사용한다. 메뉴 화살표와 즉시 닫히는 팝업은 제거했다.
- 전체 캘린더: 로컬/ICS 추가, 검색과 서비스 필터, 표시·색상·기본 저장 대상, ICS 활성화·선택 구독 새로고침을 관리한다.
- Google 세부 설정: 연결·Google 쓰기 대상·동기화·진단·가이드만 제공한다. 중복 ICS 구독과 로컬 캘린더 관리 코드를 제거했다.
- Google 화면의 전체 캘린더 관리 버튼은 공통 관리 화면으로 돌아간다. 허브에서 연 자식 다이얼로그는 중첩된 허브를 새로 열지 않는다.

## 검증 환경에서 발생한 설정 문제

첫 미리보기는 `QSettings.setDefaultFormat()`/`setPath()`만 적용해 Windows의 조직/앱 이름 생성자를 충분히 격리하지 못했다. 일반 사용자 레지스트리의 테마·동기화 설정 3개와 데모 ICS 오류 키 2개에 데모 값이 들어갔다. Store 앱의 별도 레지스트리 하이브를 읽어 보존된 설정을 확인하고, 그 기록을 기준으로 3개 설정을 복구하고 데모 키 2개를 제거했다. 최초 일반 사용자 레지스트리의 사전 스냅샷은 없어 복구 기준은 Store 설정 기록이다.

검증 도구를 모든 QSettings 생성자를 임시 INI로 바꾸는 방식으로 수정했다. 이후 테스트·미리보기·실제 창 검사는 각각 사용자 설정 전체의 실행 전후 동일성을 확인했다. 미리보기의 DB/계정 데이터는 임시 경로와 예제 값이다.

## 남은 실환경 확인

사용자 Google 계정으로 Desktop OAuth 로그인, 실제 외부 서비스의 일정 생성/수정/삭제 왕복, MSIX 패키지의 설치/업데이트 경로는 이번 로컬 검증에 포함하지 않았다. 현재 스토어 설치본에는 소스 변경이 적용되지 않았으며 별도 빌드·배포가 필요하다. 네트워크/권한/서비스 정책에 따른 모든 외부 오류가 발생하지 않는다는 보장은 하지 않는다. 해당 오류에서 화면이 응답하고 데이터가 보존되도록 처리와 회귀 검증을 보강했다.
