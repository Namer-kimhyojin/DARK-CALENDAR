# 연결 화면 버튼 역할 정리 — 2026-10-07

사용자가 지적한 ‘다른 서비스 연결’과 ‘시간대 · 자동 갱신 설정’의 동일한 전체 폭 버튼을 서로 다른 위치와 역할로 재편했다. 연결 및 구독 탭의 오른쪽 위에는 작은 **공통 설정** 버튼을 두고, 시간대 저장과 전체 자동 갱신 조작은 그 버튼 아래의 설정 카드로 모았다. **추가 계정 연결**은 Google·ICS 카드 아래에 별도 제목과 Outlook·iCloud·네이버 안내를 두고 작은 **서비스 목록 펼치기/접기** 버튼으로 조작한다.

두 펼침 상태는 독립적이다. 시간대 입력 초안은 다른 영역을 펼치거나 접어도 유지되며, 연결·진행 중·오류가 있는 서비스는 추가 목록을 접어도 보인다. 전체 계정이 연결되면 추가 연결 안내만 숨긴다. 접힘 상태의 화살표와 활성 배경, 변경되는 동작 문구 및 접근성 이름으로 상태를 구분했다. 기존 계정 설정·동기화·시간대 저장과 자동 갱신 처리 경로를 재사용했다.

Windows 작은 창 검증 중 1040px에서 640px로 폭을 바꿀 때 서비스 스크롤의 선호 높이가 창에 전파되어 500px 요청이 688px로 강제 확대되는 현상도 확인했다. 허브의 스크롤 래퍼가 내용의 선호 높이를 창 높이로 강제하지 않도록 수정해 내용은 스크롤로 접근하게 했다. 공통 다이얼로그 스타일이나 다른 화면의 레이아웃은 변경하지 않았다.

제품 변경은 `calendar_sync_hub.py`, `calendar_sync_style.py`와 19개 로케일의 `sync_disclosures` 문자열이다. 한국어·영어를 제공하고 나머지 17개 언어에는 영어 대체 문자열을 제공했다. 실제 사용자 DB·계정·네트워크를 사용하는 검증이나 릴리스 작업은 수행하지 않았다.

격리 검사 **103개**가 통과했다. 기존 흐름·번역 74개, 새 펼침/설정 검사 17개, 인코딩 12개이며 반복 실행은 합산하지 않았다. 펼침의 마우스·Space 조작, 초안 보존, 활성 계정 카드 유지, 시간대 저장의 유효/무효/진행 중 처리, 연결된 서비스만 전체 자동 갱신을 변경하는 정책 및 전용 탭의 기존 흐름을 확인했다. [기존 흐름·19개 로케일](../../artifacts/calendar-service-disclosures-20261007/root/final-flows.xml), [새 상호작용 검사](../../artifacts/calendar-service-disclosures-20261007/root/agent-disclosures-final-current.xml), [인코딩](../../artifacts/calendar-service-disclosures-20261007/root/encoding.xml)에 결과를 기록했다. 실제 사용자 설정을 보존했고 범위 Ruff·Python 컴파일·diff 검사를 통과했다.

`scripts/run_encoding_guard.py`도 작업 전용 TEMP와 pytest basetemp를 사용한 재실행에서 통과했다. 최초 일반 실행의 인코딩 1개 fixture 오류는 샌드박스 기본 TEMP의 디렉터리 생성 실패였으며, 코드 오류와 구분했다. 기존 두 pytest 캐시 폴더의 읽기 권한 경고는 유지했고 관련 없는 폴더나 권한은 변경하지 않았다.

Windows 네이티브 Qt의 밝음·어두움과 실제 100%·150% 배율 4조합에서 최종 조건 **332개**, 캡처 **56개**를 확인했다. Qt·배치·Python 콜백 오류는 0건이고 소스 해시와 개인 설정 보존을 확인했다. 640×500으로 한 번에 크기를 변경해도 강제 확대가 없으며, 다섯 탭을 실제 클릭한 뒤 닫기 버튼의 전체 접근과 닫기 동작도 유지한다. 150% 배율의 넓은 창은 검증 장치의 1080px 화면에 맞춘 공통 최대 높이 632px 제한을 따르므로 스크롤로 접근하며, 1040×840 전체 배치 이미지는 실제 100%에서 제공한다.
