# 주간 시간표 투명도와 사용 편의성 개선

확인일: 2026-10-07. 사용자가 첨부한 화면에서 시간표가 주변 패널보다 불투명하게 보이는 문제와 주간 일정 관리의 편의성을 개선했다.

## 변경한 화면과 동작

- 시간표의 배경은 주변 패널과 같은 `bg_main` 투명도를 사용한다. 부모 캘린더 표면만 배경을 그리고, 시간표·스크롤 영역·뷰포트·캔버스가 배경을 중복해서 칠하지 않는다. Qt 기본 배경색과 미리 합성하여 불투명하게 만들던 처리를 제거했다.
- 일정 카드는 `content_bg`의 읽기용 최소 투명도를 유지한다. 사용자 캘린더 색상이 반투명이어도 카드 배경의 가독성은 유지한다. 오늘 열과 선택 날짜는 옅은 강조색을 사용한다.
- 상단 투명도 슬라이더를 움직이면 현재 시간표 배경도 즉시 갱신한다. 드래그·선택·스크롤 위치와 원본 일정 데이터를 유지하고, 같은 스타일을 다시 적용하지 않는다.
- **현재 시간**은 보고 있는 날짜를 유지하며 현재 시각의 한 시간 전부터 보이도록 이동한다. **09:00**은 오전 9시로 이동한다. 명시적 이동 위치를 저장하며, 기존에 저장한 00:00 위치도 유효한 값으로 복원한다.
- 선택 날짜는 요일 헤더의 밑줄과 옅은 배경으로 표시한다. 실제 오늘 표시는 별도로 유지한다. 날짜를 클릭하면 상단 날짜 표시와 오늘 버튼 상태도 즉시 갱신하고 왼쪽 일정 패널만 새로 그린다.
- 일정 생성·이동·기간 조절의 드래그 미리보기에 시간 범위와 소요 시간을 표시한다. 짧은 블록에서는 범위를 벗어나는 글자를 잘라 표시한다.
- 주간 시간표의 도구모음을 두 줄로 배치했다. 날짜 이동·추가·동기화·옵션은 첫 줄, 시간 이동·보기 전환·사용 방법은 둘째 줄에 배치하여 760px 창에서도 버튼과 7개 요일이 잘리지 않는다.
- **사용 방법** 버튼은 클릭 또는 키보드로 기존 시간표 조작 안내를 표시한다.

저장·동기화·읽기 전용 캘린더의 권한 처리와 DB 스키마는 변경하지 않았다. 수정은 `week_time_grid.py`, `month_renderer.py`, `theme_actions.py`와 새 검증 파일에 한정한다. UI 문자열 5개를 한국어·영어에 추가했고 다른 17개 번들에는 같은 키와 영어 값을 제공한다.

## 검증 근거

- 관련 테스트 11개 파일을 각각 독립 Python 프로세스로 실행했다. 최종 검증은 **173개 테스트와 subtest 12개 통과**, 실패·오류·건너뜀 0개였다. 최종 화면·성능 수정의 영향을 받는 파일도 재검사했고, 최초 결과를 포함한 20개 프로세스 실행 기록을 보존했다. [최종 검증 결과](../../artifacts/week-planner-ux-20261007/final-validation-summary.json)
- 외관 검사는 실제 Qt 픽셀을 사용한다. 밝음·어두움, 투명도 0·35%·100%, 배경을 한 번만 그리는지, 카드 가독성, 선택 날짜 표시, 투명도 갱신 중 상태 보존을 검증한다.
- 실제 캘린더 렌더러로 화면 7종을 생성했다. 밝음·어두움의 투명도 85/255, 760px, 150% 배율, 드래그 미리보기를 확인했다. 실제 760px 창과 도구모음 너비가 요청한 크기를 유지하고 모든 버튼이 도구모음 안에 있는지 확인했다. [화면 검증 요약](../../artifacts/week-planner-ux-20261007/preview-summary.json)
- 실제 `OverlayApp`도 Windows Qt 플랫폼에서 별도 DB·INI 설정으로 시작했다. 네 도크 표시, 최소화·트레이 콜백 복원과 창 활성화를 확인했으며 `errors=[]`, `passed=true`였다. [전체 앱 시작 결과](../../artifacts/week-planner-ux-20261007/weekly_time-windows/probe-result.json)
- 수정 Python 9개 파일의 Ruff lint·format 검사 통과. 19개 로케일의 키·타입·placeholder 구조 검사에서 누락·불일치 0개였다.
- `scripts/run_encoding_guard.py`도 종료 코드 0으로 통과했다. 기존 접근 불가 pytest 캐시 폴더 두 곳의 compileall 경고는 있었으며 최종 인코딩 검사는 통과했다.

모든 자동 검증은 별도 INI 설정에서 fallback을 차단하고 임시 SQLite·LOCALAPPDATA를 사용했다. 테스트 래퍼는 설정과 DB 접근 경로가 해당 검사 폴더 안에 있는지 검사하며, 실제 사용자 데이터나 인증 파일을 복사하는 마이그레이션도 차단한다. 실행 중인 사용자 앱을 종료하거나 실제 계정의 일정을 변경하지 않았다. 개발 소스에 적용했으며 이미 실행 중인 앱에서는 다음 실행부터 반영된다.
