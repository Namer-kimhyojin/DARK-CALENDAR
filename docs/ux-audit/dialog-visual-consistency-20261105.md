# 전체 대화상자 디자인 통일 및 상세 버튼 중복 수정

2026-11-05 개발 소스 4.9.2에 적용했다. 선택한 2번 네이비·라일락 시안의 제목, 카드, 탭, 입력란, 강조 버튼을 앱 공통 스타일로 확장했다. 제품 버전과 배포 상태는 변경하지 않는다.

## 적용 범위

- `dialog_styles.py`의 공통 기본 스타일과 표시 필터를 연결했다. 자체 스타일 또는 투명 배경이 있다는 이유로 대화상자를 건너뛰지 않는다. 전용 스타일은 공통 기본 스타일 뒤에서 유지한다.
- 정적 인벤토리는 직접 `QDialog`를 상속하는 52개와 파생 클래스를 포함한 59개 선언을 확인했다. 명시적 공통 스타일 제외 설정은 없다. 익명으로 만드는 Qt 확인·입력·날짜·위젯 설정창도 공통 경로를 사용한다. 선언 수는 실행 중 모든 기능을 직접 클릭한 횟수가 아니다.
- Google·Outlook·CalDAV·ICS와 캘린더 관리의 설정창, 위젯 관리자·라벨·이모지·실행창을 공통 스타일에 연결했다. 부모 창의 실제 색상, 크기, 사용자 토큰 설정을 전달한다.
- 알람 팝업, 집중 완료, 오늘의 브리핑·노출 설정, 집중 단계 전환 알림을 같은 제목·내용·동작 계층으로 맞췄다. 긴 설정 본문은 스크롤되고 하단 저장·취소는 유지된다.
- Qt 기본 확인창의 저장·보조·위험 버튼 역할을 통일한다. 이미 공통 스타일을 직접 적용한 확인창도 동일하게 처리하며, 삭제나 취소의 기존 기본 버튼 동작은 바꾸지 않는다.

사용자가 고른 다양한 색상, 투명도, 크기 토큰과 독립 위젯 스킨을 유지한다. 별도 위젯 스킨을 지정하지 않은 실행창은 앱 색상을 따른다. 읽어야 하는 카드에는 기존 `floating_bg`/`content_bg` 최소 불투명도 계약을 사용한다. 캘린더 데이터, 인증·동기화 엔진, 도크 이동·개별 위젯 배치의 저장 구조는 수정하지 않았다. Windows 시스템 알림은 기존 OS 표시 경로를 사용한다.

## 첨부 화면의 버튼 중복

일정 상세창을 펼칠 때마다 ‘일정 수정·완료 처리’ 버튼을 새로 만들던 경로를 없앴다. 상세 카드마다 버튼 두 개를 한 번만 만들고 현재 완료 상태에 따라 라벨과 동작 대상을 갱신한다. 내용과 크기를 준비한 뒤 떠 있는 창을 표시해 이전 행을 먼저 그리는 중간 화면도 제거했다.

- 지연 삭제 이벤트를 처리하지 않고 30회 다시 구성해도 같은 버튼 객체 두 개만 존재한다.
- 완료·미완료를 오간 뒤 클릭하면 최신 상태로 신호를 한 번만 보낸다.
- 두 일정의 상세창을 번갈아 열고 닫아도 표시 시점마다 동작은 두 개다.
- 네이비·밝음·사용자 색상·투명 모드에서 실제 상세창을 각각 20회 펼친 후 캡처했다. 모든 결과에서 동작 행은 하나다.

## 검증 근거

실제 PyQt 위젯을 임시 SQLite·INI 설정에서 렌더링했다. 외부 통신과 Python의 레지스트리 쓰기를 차단했다. 실제 사용자 DB나 계정을 검증용으로 편집하지 않았다.

| 범위 | 결과와 근거 |
| --- | --- |
| 공통 경로와 상세 버튼 | `tests/test_dialog_visual_system.py`: 부모 설정 상속, 부분 강조색, 사용자 크기·색상, 투명 외곽, 기본 확인창 역할, 반복 표시, 중복 동작 회귀 검사 |
| 태스크 편집 | 생성·수정·이동·복사·정확한 분·자정·종일·캘린더 소유 유지 관련 40개 검사 통과 |
| 연결 설정 | 관련 190개 검사와 테마 가드 11개 통과. [검증 목록](../../artifacts/dialog-visual-system-20261105/providers/verification-summary.json) |
| 위젯·관리 화면 | 9개 파일의 고유 검사 229개 통과. [적용 경로와 범위](../../artifacts/modal-consistency-20261105/long-tail-coverage.md) |
| 알람·요약·집중 | 관련 48개 검사 통과. 스누즈·완료·닫기, 결과 코드, 저장·취소, 사운드·타이머와 전환 알림 참조 해제를 포함 |
| 정적 검사 | 관련 Ruff와 인코딩 정책·컴파일 검사 통과 |

위 숫자는 범위별 결과다. 겹치는 테마·에디터 검사까지 더한 전체 고유 테스트 수로 제시하지 않는다. 저장한 XML과 렌더링 스크립트는 [공통 검증 폴더](../../artifacts/dialog-visual-system-20261105/), 알람 화면은 [알람 검증 폴더](../../artifacts/alarm-surfaces-20261105/)에 있다.

연결창 15장과 작은 화면 5장, 위젯·관리 화면 12장, 알람 계열의 세 테마와 좁은 화면을 확인했다. 메인·일정 편집창도 재렌더링해 시안의 색상·계층이 유지되는지 비교했다. 초기 연결 헬퍼의 명시적 색상 전달 오류와 공통 필터의 확인창 조기 반환은 수정 후 회귀 검사했다.

검증 중 한 초기 실행은 사용자 설정의 실행 전후 읽기 비교가 달라 관찰 검증을 통과하지 못했다. 병행 실행 중이던 실제 앱의 영향을 배제할 수 없어 원인을 단정하지 않았고, 설정을 복원하거나 덮어쓰지 않았다. 최종 재실행은 설정 차이가 없음을 확인하고 정상 종료했다. 해당 초기 실패와 후속 성공을 구분한다.

캡처는 Qt offscreen의 실제 클라이언트 렌더링이다. Windows 바탕화면 합성, OS 제목 표시줄, 실제 여러 모니터·DPI 환경, 화면 읽기 프로그램의 전체 사용 경험을 검증한 기록은 아니다. 실행 중인 개발 앱에는 종료 후 `run.bat`으로 다시 실행하면 적용된다.
