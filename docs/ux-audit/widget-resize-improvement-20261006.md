# 위젯 크기 조절 개선 — 2026-10-06

## 문제와 변경

KeyDeck의 드래그 중 창은 사용자가 지정한 사각형으로 커졌지만 덱 그림은 그 안에서 별도 비율로 맞춰졌습니다. 따라서 투명한 여백과 크기 조절 경계가 크게 남았습니다. 이제 임시 확대와 저장 확대 모두 실제 덱 기하에 맞춰 창·face·canvas를 같은 크기로 맞춥니다. 확대 범위는 60–220%이며 임시 확대값은 종료 전까지 덱 데이터에 저장하지 않습니다.

덱 자체의 그림자 여백까지 조절 영역에 포함해 실제로 보이는 케이스의 변을 직접 잡을 수 있습니다. 조절 표시도 케이스 바로 바깥에 놓습니다. 키와 헤더 컨트롤은 우선 동작하며 타이틀의 이동 영역도 보존합니다.

기존 공통 조절 영역은 사각형의 22px 모서리 네 곳뿐이었습니다. Windows 실제 마스크 검사에서 원형 300×300과 캡슐 400×200의 네 영역은 모두 입력 마스크 밖에 있었습니다. 이제 네 변과 네 모서리를 제공하고 곡선 위의 접근 가능한 구역에 커서와 표시를 배치합니다. 작은 위젯에서는 조절 영역도 줄여 중앙 콘텐츠와 이동 영역을 확보합니다.

KeyDeck과 모양 위젯은 자동으로 비율을 유지합니다. 카드 위젯은 자유 크기와 Shift 비율 유지 동작을 제공합니다. 실제 보정된 크기로 반대 모서리 또는 반대 변 중심을 고정해 드래그·종료·확대 한계에서 위치가 뛰지 않도록 했습니다. 음수 모니터 좌표와 홀짝 크기 변경의 중심 반올림도 처리합니다.

공통 위젯의 화면 크기 제한은 드래그 중과 종료 후 같은 기준으로 적용합니다. 모양의 너비·높이를 함께 제한해 원형이 타원이 되는 현상을 방지합니다. 포스터의 너비 제한에서 발생하는 1px 높이 반올림도 최초 적용부터 안정된 값으로 계산하므로 설정을 반복해서 읽거나 다시 표시해도 크기가 바뀌지 않습니다.

KeyDeck의 기본 포커스 정책을 유지하면서 Esc 취소를 제공하기 위해, 실제 배치가 시작되는 OS 드래그 거리를 넘은 동안에만 keyboard grab을 사용합니다. 조절 종료·취소·잠금·입력 유실·숨김에서 해제합니다. 평소 키 클릭과 작은 흔들림에는 키 입력을 가져오지 않습니다.

## 검증 범위

- 순수 기하: 8방향, 확대·축소·크기 제한, 비례 크기, 작은 위젯, 음수 화면 좌표, 마스크 밖 제외.
- 실제 위젯: 곡선 위 hit-test·표시·커서, 자유형 변 조절, Shift 비율, 자동 모양 비율, 되돌리기, 클릭 흔들림, 잠금, 입력 유실, Esc.
- KeyDeck: live·종료·초기화·숨김·복원 크기 정합성, 확대 한계, 임시 상태 보존, 반대 앵커, 키·헤더 버튼 우선 처리.
- Windows 네이티브 렌더: 비정상적인 드래그 `(310, 30)`에도 332×286에서 641×552로 비율 조정, live와 종료 크기 일치, 콘텐츠 offset `(0, 0)` 확인.
- Windows 배율 100%·150%에서 실제 화면을 생성하고, 활성 조절 중 keyboard grab 획득과 종료 후 해제를 확인합니다.

검증 과정은 모든 QSettings 생성자를 격리했고 사용자의 기존 설정 보존을 확인했습니다. 실제 사용자 DB·계정·설정을 변경하지 않았습니다. 이 문서는 로컬 소스 개선과 검증 결과를 기록하며 Store 설치본에 반영된 상태를 의미하지 않습니다.

최종 크기 조절 검사는 공통 위젯 64개와 KeyDeck 53개가 모두 통과했습니다. 확장 회귀 582개, 순수 기하 63개, 추가 기존 동작 검사와 인코딩 정책·Ruff·변경 범위 검증도 통과했습니다. 반복 실행 수는 합산하지 않습니다. Windows 100%·150% 배율의 네이티브 캡처에서도 케이스 가장자리 조절, 창/콘텐츠 크기 일치, 키보드 grab 획득·해제를 확인했습니다.
