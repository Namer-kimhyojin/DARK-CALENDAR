# 캘린더 목록에서 기본 저장 지정 — 2026-10-07

캘린더 관리의 ‘내 캘린더’ 목록에서 각 행의 ‘기본 저장’을 선택해 새 일정의 기본 캘린더를 지정한다. 별도 상단 선택 상자와 오른쪽 상세 영역의 기본 지정 버튼을 제거해 저장 위치를 설정하는 흐름을 목록 하나로 통합했다. 개발 소스와 격리 검증 결과이며 Store 설치판 업데이트와 실제 계정 동기화는 수행하지 않았다.

## 동작과 배치

- 캘린더 이름·서비스 정보 옆에 기본 저장 라디오를 배치한다. 전체 목록에서는 사용 가능한 기본 대상 하나만 선택되며, 검색으로 기본 캘린더가 제외돼도 다른 행을 기본값처럼 표시하지 않는다.
- 목록 행 선택은 상세 정보를 열고, ‘기본 저장’ 선택은 저장 위치만 변경한다. 다른 행을 기본값으로 지정해도 기존 상세 선택·검색·서비스 필터·스크롤·키보드 포커스를 유지한다.
- 클릭과 키보드 Space로 지정한다. 이미 기본인 행은 다시 저장하지 않는다. 긴 이름과 출처는 줄임표로 표시하고 전체 내용을 툴팁에 제공한다. 좁은 창에서도 기본 저장 제어가 보인다.
- 읽기 전용·가져오기 미선택 대상은 기본 저장 지정을 제한하고 이유를 안내한다. 화면에서 숨긴 쓰기 가능한 캘린더는 기본 저장 위치로 사용할 수 있다. 화면 표시 설정은 별개로 유지한다.
- 공통 `calendar_preferences.set_default_calendar()`를 사용해 DB와 기존 Google 호환 설정을 함께 반영한다. 새 일정 생성창은 지정한 `calendar_id`로 시작하며 기존 일정 소속·Google 연결·삭제 대기열을 옮기지 않는다.
- 저장 거부나 DB 예외가 발생하면 이전 저장값으로 라디오를 복구한다. 목록 수신 뒤 권한이 바뀐 경우에도 저장소 정책이 지정 가능 여부를 재확인한다. 저장된 기본값이 없을 때는 저장소와 같은 활성·쓰기 가능 대상을 표시하며 DB를 임의로 재작성하지 않는다.
- 오른쪽 상세의 표시 관련 구역은 ‘화면 표시’로 정리한다. 신규 안내 5개를 한국어·영어에 작성하고 나머지 17개 로케일에는 영어 대체 문자열을 제공한다.

## 검증

중복을 제외한 관련 검사 **214개**가 통과했다(기능·회귀·번역 202개, 인코딩 정책·유틸리티 12개). 동일 사례를 재실행한 경우 최신 결과로 집계했으며 미해결 실패·오류·건너뛴 검사는 없다. 전체 저장소 테스트를 완료했다는 의미는 아니다.

신규 목록 지정 검사 22개는 실제 임시 SQLite·INI에서 클릭·Space, 단일 기본값, 권한 제한, 실패 복원, 검색·선택·스크롤·포커스 보존, 새 일정 초기값과 기존 일정 소속 보존을 확인한다. 관련 5개 파일의 회귀 124개를 통과했고 마지막 행 렌더 수정 뒤 신규 22개를 다시 통과했다.

Windows 네이티브 Qt에서 한국어 어두운 테마 100%·밝은 테마 150%, 폭 620·760px의 최종 화면 6개와 UI 조건 76개를 확인했다. geometry 경고는 없고 개인 QSettings를 보존했다. 원본 PNG와 요소 상태를 함께 검토했다. 초기 검증에서 발견한 잘못된 테마 토큰과 기본 목록 장식 공간·이중 선택 테두리는 수정 후 재검증했다.

수정 범위의 Ruff, UTF-8 헤더·컴파일과 diff 공백 검사도 통과했다. 집계와 최종 소스·로케일 해시는 [summary.json](../../artifacts/calendar-list-default-20261007/summary.json), 원본 회귀 결과는 [기능 검증 보고서](../../artifacts/calendar-list-default-20261007/provider-tests/VERIFICATION.md), 네이티브 조건은 [화면 검증 집계](../../artifacts/calendar-list-default-20261007/qa/native-summary.json)에 기록했다.
