# Store 설치판 Google 인증 오류 개선

검토일: 2026-10-06 KST

## 확인된 원인

- 설치 패키지: `Kimhyojin.DarkCalendar`, `3.8.0.0`, x64 (현재 PC에서 조회).
- 제공된 Google 오류 화면: `400 redirect_uri_mismatch`.
- 현재 앱 데이터의 인증 파일은 `web` 유형이며 다른 웹 서비스의 HTTPS 콜백으로 등록되어 있었다. 클라이언트 ID, 비밀값, 계정과 전체 콜백 주소는 이 기록에 포함하지 않는다.
- 기존 설정 화면은 `authenticate(self)`를 UI 스레드에서 직접 호출했다. `run_local_server(port=0)`에는 시간 제한이 없어, Google이 브라우저에서 요청을 거절하고 로컬 콜백을 보내지 않으면 UI가 계속 대기한다.
- 기존 재인증은 인증 시도 전에 토큰을 삭제해 실패해도 기존 연결 정보를 잃을 수 있었다.

## 수정

- `oauth.py`: Desktop (`installed`) OAuth JSON을 사전에 검증하고 웹용·잘못된 파일을 안내한다. Google의 인증/토큰 엔드포인트만 허용한다.
- 로컬 콜백은 `127.0.0.1`의 임의 포트에만 바인딩하며 OAuth state와 경로를 검증한다. 잘못된 state나 favicon 요청으로 인증을 완료하지 않는다.
- 브라우저 응답 대기는 180초, 토큰 교환과 Google API HTTP 요청은 12초 제한을 사용한다. 콜백 대기 중 취소는 0.2초 간격으로 확인하며 연결 요청의 읽기도 제한한다.
- `GCalAuthWorker`: 로그인과 캘린더 조회를 UI 밖에서 수행한다. 시작 전 또는 종료 직후의 취소 요청도 별도 이벤트로 유지한다.
- 인증 버튼은 대기 중 취소 버튼이 된다. 저장·연결 초기화는 대기 중 비활성화하며, 창 닫기는 취소 후 스레드 종료 시 완료한다. 네트워크 요청 중에는 해당 요청 제한까지 종료가 늦어질 수 있으나 화면 이벤트는 계속 처리한다.
- 새 인증 결과는 별도 서비스에 준비하고 성공 결과를 UI가 수락한 후 토큰과 서비스에 반영한다. 실패·취소·창 닫기는 기존 연결을 보존한다.
- `token_store.py`: 임시 파일을 쓰고 원자적으로 교체하여 저장 실패 시 기존 토큰 파일을 보존한다.
- 인증 성공 후 캘린더/계정 표시는 워커의 조회 결과를 재사용한다. 이 완료 흐름에서 UI 스레드의 추가 Google 조회를 제거했다.
- 새 오류·대기·취소 안내에 한국어와 영어 번역을 추가했다. 동기화 사용 해제는 잘못된 인증 파일 때문에 차단하지 않는다.

## 검증

- Google 동기화, 인증, 설정 UI, 백그라운드 워커, 인코딩, 공통 동기화 번역 회귀: **160 passed**.
- 마지막 계정 표시 수정 후 인증·설정 UI·Google 서비스 재검증: **92 passed**.
- 인코딩 가드, 관련 Ruff 검사, 변경 파일 `git diff --check`: 통과.
- 실제 로컬 HTTP 콜백으로 잘못된 state, 다른 경로, 성공, 권한 거절, redirect 오류, 서버 종료를 검증했다.
- 응답 없음, 브라우저 실행 실패, 취소, UI 타이머 반응, 창 닫기, 재시도, 웹용 파일의 복사 전 차단, 기존 연결과 토큰 파일 보존을 검증했다.
- 사용자 DB와 계정에 쓰지 않도록 테스트/미리보기는 별도 LOCALAPPDATA와 테스트 QSettings를 사용했다. 빈 미리보기 DB의 진단 테이블 없음 로그는 실사용 DB 오류로 판단하지 않았다.
- 오프스크린 화면에서 인증 대기와 오류 안내의 줄바꿈·버튼·전체 문구 표시를 확인했다. 오프스크린 환경에는 시스템 폰트가 자동 등록되지 않아 미리보기에 Windows 맑은 고딕을 명시적으로 등록했다.

## 남은 적용과 사용자 조치

- **소스 수정 및 로컬 검증 완료. Store 배포·설치 업데이트는 이 작업에서 수행하지 않았다.** 설치판 `3.8.0.0`에는 새 동작이 아직 반영되지 않았다.
- 실제 Google 계정 로그인은 새 Desktop OAuth JSON이 필요하므로 아직 검증하지 않았다. 웹용 JSON의 키 이름이나 콜백 주소만 수정해서 Desktop 클라이언트로 사용할 수는 없다.
- Google Cloud의 OAuth 클라이언트를 **데스크톱 앱** 유형으로 새로 생성하고 JSON을 다운로드한 다음 Air Calendar의 파일 선택으로 지정한다. 계정 접근 설정과 Google Calendar API 활성화도 해당 프로젝트에서 확인한다.
- 사용자의 현재 인증 파일·토큰·DB·기존 개발 변경분을 자동 교체하거나 초기화하지 않았다.

공식 근거: [Google Desktop OAuth 및 loopback 지원](https://developers.google.com/identity/protocols/oauth2/resources/loopback-migration), [OAuth 클라이언트와 redirect URI 오류](https://support.google.com/cloud/answer/15549257?hl=en).
