# 계정 연결·동기화 UI/UX 및 오류 개선 — 2026-10-07

개발 소스에서 Google·Outlook·iCloud·네이버 설정과 전체 캘린더 관리의 계정 복구 흐름을 개선했다. 실제 계정·일정·구독 서버에 접속하지 않고 임시 SQLite·INI와 가짜 서비스 응답으로 검증했다. 설치된 Store 앱 반영과 실제 계정 재인증은 별도 검증 범위다.

## 변경 내용

- 동기화 일시정지와 계정 연결 해제를 구분한다. Google 동기화를 꺼도 연결·서비스·토큰은 유지한다. Google의 새 일정 가져오기 선택을 모두 끈 경우에도 기존 일정 편집 전송은 가능하다.
- Google 설정을 저장하고 닫거나 실행 중인 인증 작업이 일시정지를 관찰해도 기존 인증 서비스를 초기화하지 않는다. 재개 시 기존 연결을 사용하고 자동 타이머를 다시 시작한다. 백그라운드 인증 중에는 별도 동기화를 시작하지 않으며, 작업 시작을 인증 성공으로 안내하지 않는다. 인증 작업 정리 후 진행 중 상태도 갱신한다.
- 인증 만료·계정 확인 실패는 다시 연결, 캘린더 미선택·권한 상실은 캘린더 선택, 미처리 일정은 문제 확인으로 안내한다. 자동 동기화·수동 갱신·설정 진입은 현재 상태에 따라 활성화한다.
- Google의 실제 `auth`·`auth_required`·`reauth_required`와 API 401을 재인증 상태로 보존한다. 403·429는 인증 만료로 묶지 않는다. 상세 응답·비밀 문자열은 상태 코드에 저장하지 않는다.
- Outlook·CalDAV도 재시작·선택 저장·취소 후 저장된 인증 오류가 남아 있으면 다시 연결로 안내한다. 정상 상태 이름만 보고 인증 실패를 숨기지 않는다.
- 요청 제한의 남은 대기 시간을 표시하고, 수동 버튼으로 서버가 지정한 대기를 우회하지 않는다. 공개 읽기 전용 controller 속성으로 기존 대기 로직을 조회한다.
- 작업 중에도 설정 화면을 열어 진행 상태와 취소·중단 요청에 접근할 수 있다. 변경 입력을 잠그고 기존 계정과 선택 내용을 유지한다.
- 동기화 시작 안내는 완료·확인 필요·완료 확인 불가 안내로 이어진다. 갱신 기록 없이 성공을 표시하지 않는다. 명시적으로 거부된 Google 작업을 시작했다고 표시하지 않는다.
- 상태 갱신만으로 캘린더·문제 목록을 재생성하지 않는다. 데이터가 바뀌면 선택·검색·스크롤을 보존하고, 같은 계정의 미저장 체크 초안도 유지한다. 계정이 바뀌면 이전 계정의 선택 초안을 가져오지 않는다.
- 공급자 설정의 반복 상태 안내는 DB를 재조회하지 않는다. 목록 변경·상태 전환·작업 완료·로컬 설정 조작 때 다시 읽는다. 중단 요청을 일반 실패 횟수에 추가하지 않으며, 연결 해제는 정리가 완료될 때까지 결과를 받는다.
- Google 화면에 상단 인라인 안내·다음 행동·입력 잠금·취소를 추가하고 인증 파일 도움말을 접는다. 잘못 저장된 숫자 설정을 기본값·범위로 복구한다. 저장 후 창을 유지하며, 닫을 때 호출부가 저장 적용 여부를 받을 수 있도록 기존 계약을 보완한다.
- 앱 시작·재개 경로에서도 잘못된 동기화 간격은 기본값으로 처리하고 큰 값은 Qt 타이머의 안전한 범위로 제한한다. 기존 0분 설정의 자동 타이머 중지 동작은 유지하며, 저장 전 사용자 설정을 재작성하지 않는다.
- Outlook·CalDAV 화면은 계정 연결·가져올 캘린더·문제 해결로 정리한다. 기술적 연결 준비 안내를 접고, 작은 창에서는 세로 스크롤을 제공한다. 동기화 버튼은 선택 저장 성공 후 작업을 시작한다.
- 전체 관리의 작은 창에서는 서비스 카드 버튼을 세로로 배치하고, 필요한 복구 행동을 강조한다. 읽기 전용·표시 여부·기본 저장 위치의 기존 계약은 유지한다.
- 새 한국어·영어 안내를 19개 번들 로케일에 반영한다. 나머지 17개 로케일의 새 안내에는 영어 대체 문자열을 제공한다.

## 검증 근거

중복을 제외한 관련 검사 575개가 통과했다(기능·회귀 563개, 인코딩 정책·유틸리티 12개). 실행별 원본 결과와 동일 사례의 최종 결과를 비교한 집계에서 미해결 실패·건너뛴 검사는 없다. 전체 저장소 테스트 완료를 뜻하지 않는다. 최종 테스트·렌더 집계는 `artifacts/account-sync-ux-20261007/summary.json`에 기록했다. 테스트는 실행별 앱 데이터·설정·임시 파일 경로를 분리하고 QApplication 생명주기를 고정했다. 네이티브 사용자 QSettings 보존도 확인했다.

네이티브 Qt QA는 실제 버튼 클릭·키보드·창 크기·요소 geometry와 PNG를 함께 확인한다. 네트워크·브라우저 접속을 차단한 가짜 계정 화면으로 어두운 테마 100%, 밝은 테마 150%, 좁은 창을 검증한다.

총 69개 화면 캡처와 130개 UI 조건이 통과했고 geometry 경고는 없었다. 17개 수정 소스·테스트의 UTF-8 헤더·컴파일과 범위 제한 Ruff 검사를 통과했다. UI 소스 13개와 캡처의 해시는 `qa/native-summary.json`, 이후 Google 실행 경로 보완의 최종 해시는 전체 `summary.json`에서 구분해 기록한다.

초기 검증에서 발견한 Google 인증 오류의 일반 오류 변환, Outlook 작은 창 높이 초과·미선택/대기 중 갱신 활성·체크 초안 손실을 구현과 회귀 사례로 보완한다. 로컬 인증 콜백 3개는 샌드박스 소켓 제한으로 초기 실패한 뒤 localhost만 사용하는 별도 실행에서 통과했다. 실제 Google 인증을 수행한 결과가 아니다.

기본 인코딩 guard는 전체 Python 컴파일 단계 후 샌드박스 기본 임시 폴더 생성 오류로 한 테스트가 시작되지 못했다. 저장소 내 별도 임시 경로로 같은 인코딩 정책·유틸리티 12개를 실행하여 모두 통과했다. 기존 접근 제한된 두 임시 폴더는 건드리지 않았다. QObject만 사용하는 일부 테스트의 QApplication 수명 문제도 실행기에서 고정한 뒤 해당 사례를 다시 통과시켰다.

## 남은 실제 환경 검증

- 사용자 계정에서 최초 연결·재인증·권한 만료·계정 해제, 실제 서버 요청 제한, 자동/수동 동기화와 구독 피드 확인.
- Store 패키지 빌드·제출·설치 업데이트 및 설치판 동작 확인.
- 이전 계정 식별자가 없는 오래된 Google `primary` 데이터의 계정 소속 복원과 전체 계정 교체 정책. 기존 [외부 동기화 안전 점검](external-sync-boundary-audit-20261007.md)의 보호 규칙을 유지한다.
