# 캘린더 동기화 · 연결 UI/UX 점검 (2026-10-05)

현재 개발 폴더에 iCloud·네이버 CalDAV 연결을 구현하고 Google·Outlook과 함께 사용할 때의 격리, 오류 복구와 설정 화면을 검증했다. 실제 사용자 DB·계정·일정은 테스트에 사용하지 않았다. 이 문서는 개발 코드의 검증 기록이며 릴리스·Store 제출·설치 완료 기록과 구분한다.

## 구현 및 개선

| 영역 | 처리 결과 |
|---|---|
| CalDAV 연결 | principal/home 탐색, 캘린더 목록·권한 확인, 범위 REPORT, ETag 조건부 수정·삭제, 고정 UID로 생성 재시도 |
| 서비스 범위 | iCloud 개인 일정은 권한에 따라 양방향. 네이버는 읽기 전용. 반복·초대 일정은 조회 전용 |
| 인증 | 성공한 연결만 Windows DPAPI 사용자 범위로 암호화 저장. 암호 숨김·표시 선택, 작업 시작 후 입력칸 비우기 |
| Google 라우팅 | Outlook/CalDAV 소유 일정에 이전 Google 필드가 남아 있어도 Google 쓰기로 보내지 않음 |
| 공통 엔진 | 계정별 실행 잠금, SQLite 잠금 후 동시 수정 재확인, 원자적 캘린더 선택 저장, 서버 기본값 반영으로 반복 전송 방지 |
| 내용 충돌 | ETag만 바뀌면 내용 충돌로 만들지 않음. 로컬·원격 내용 비교와 버전 선택. 비교 후 로컬 수정 시 오래된 해결 선택 거부 |
| 원격 삭제·삭제 실패 | 로컬 사본 보존. 원격 내용 변경·조회 전용 삭제는 자동 재시도 보류. 삭제 재시도/취소는 계정·캘린더별로 격리 |
| 네트워크·예외 | 부분 REPORT와 잘못된 XML/ICS를 빈 정상 결과로 취급하지 않음. 인증/권한/호출 제한/서버 오류 때 이후 쓰기 중단. 자동 재시도 간격 확대 |
| 프로토콜 호환 | iCloud 샤드 서버 탐색 허용, 서비스 외 호스트로 인증정보 전달 차단. HTTP 헤더 대소문자와 무관하게 ETag 읽기 |
| 일정 UI | 읽기 전용 캘린더를 새 일정 저장 대상으로 선택하지 못하도록 처리. 기존 생성·수정·이동/드롭 흐름 회귀 검사 |

## 설정 화면 검토

통합 설정에서 네 서비스의 연결 여부·지원 범위·자동 동기화·최근 성공을 확인한다. 공통 시간대는 유효한 IANA 값만 저장하며 동기화 진행 중 변경을 막는다. CalDAV는 계정 연결 → 캘린더 선택 → 문제 확인의 세 탭으로 구성했다.

- 잘못된 인증, 권한 부족, 서비스 제한, 인터넷 오류, 호출 제한, 충돌에 대해 사용자가 취할 조치를 표시한다.
- 캘린더의 양방향/읽기 전용을 각 행에 표시하고 사용자 지정 이름·색상·표시 설정을 보존한다.
- 작업 중 계정·선택·해결 버튼을 잠그고 해당 항목을 선택했을 때만 충돌/삭제 버튼을 활성화한다.
- 일반 상태 갱신이 저장 전 캘린더 체크를 지우지 않도록 했고 다른 서비스의 신호가 현재 편집에 끼어들지 않도록 했다.
- 한국어/영어 × 밝음/어두움 × 통합/연결/선택/충돌/네이버 화면 20개를 임시 DB와 설정으로 렌더링했다. 주요 화면의 텍스트 줄바꿈·버튼·대비·암호 입력·선택 표시를 직접 확인했다.
- 스크롤 뷰포트의 흰 배경이 어두운 카드 뒤에 비치던 문제와 어두운 테마의 캘린더 선택 표시를 수정했다.
- 19개 로케일의 키·자료형·치환값 정합성을 검사했다. 새 문자열은 한국어·영어로 제공하며 다른 언어에는 영어 대체값을 적용했다. 전체 언어의 번역 품질 검수는 별도다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| CalDAV·공통 엔진·Outlook 인증/Graph·서비스 격리 | 72 통과 |
| 연결 UI·통합 설정·기존 메뉴·초기화 회귀 | 19 통과 |
| 기존 Google 동기화 관련 회귀 | 74 통과 |
| 태스크 스타일·수정 다이얼로그·드롭 | 31 통과 + 하위 검사 7 통과 |
| i18n 구조·실행 지원 | 15 통과 |
| 인코딩 정책·유틸 | 별도 실행에서 8 + 4 통과 |
| 런타임 의존성 lock | 42개 설치 버전 일치 |
| 새 동기화 모듈 Ruff, Python 컴파일, git diff 공백 검사 | 통과 |

통합 인코딩 가드는 종료 코드 0 및 검사 통과를 반환했지만 실행 중 Windows access violation 진단이 출력됐다. 해당 정책·유틸을 별도 프로세스로 다시 실행했으며 모두 진단 없이 통과했다. Qt 검사는 offscreen 환경에서 실제 폰트 파일을 명시해 별도 실행했고 최종 실행에 네이티브 예외가 없었다. 처음 잘못 지정한 테스트 파일명으로 수집이 실패한 명령은 실제 파일명을 확인하여 다시 실행했다. JUnit 및 최종 범위는 [검증 기록](../../artifacts/sync-review/validation.json)에 기록한다.

## 남은 확인

1. 실제 iCloud 앱 전용 암호 및 네이버 인증으로 캘린더 탐색·재시작·연결 해제를 확인한다. 네이버의 Windows 연결 허용은 서비스 정책에 따르며 지원 제한을 우회하지 않는다.
2. 별도 테스트 캘린더에서 iCloud 생성·수정·삭제, 오프라인 후 복구 및 일광절약시간 전환 경계의 시간 해석을 확인한다. Microsoft 계정은 캘린더 연동용 Entra 앱 등록 후 검증한다.
3. 현재 전체 개발 입력을 포함해 릴리스 빌드와 동결 실행을 검증하고, Store 제출/설치 앱에서 별도 확인한다. 이번 작업에서 빌드·제출·설치 업데이트를 수행하지 않았다.
4. CalDAV sync-token 증분 조회와 리소스 URL 변경 시 UID 재연결은 후속 개선이다. 전체 조회 범위는 지난 120일~앞으로 400일이며 원격 삭제나 연결 해제 때문에 로컬 사본을 자동 삭제하지 않는다.

연결 순서와 서비스 공식 인증 안내는 [CalDAV 설정](../caldav_sync_setup.md), 다중 서비스 계약은 [동기화 안전 점검](../calendar_sync_safety.md)을 참고한다. 홈페이지 요청 수집은 성공했고 현재 요청 0개를 확인했다.
