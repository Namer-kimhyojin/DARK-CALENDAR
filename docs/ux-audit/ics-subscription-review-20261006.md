# ICS 구독 점검 및 보완 — 2026-10-06

요청: 통합 동기화 허브의 ICS 구독 기능을 점검하고 복구 경로를 보완한다.
이 기록은 현재 개발 폴더의 구현·검증 결과다. 실행 중인 앱이나 Store 설치본의 업데이트 완료를 뜻하지 않는다.

## 확인한 문제와 변경

| 문제 | 변경 후 동작 |
|---|---|
| 구독 주소가 만료돼도 주소 수정 경로가 없음 | 전체 캘린더에서 ICS 구독 선택 → **구독 주소 수정**으로 이름·주소 수정 |
| HTTP 권한 거부·주소 없음·요청 제한·서버 장애가 모두 네트워크 오류로 보임 | 401/403, 404/410, 429, 5xx를 개별 오류로 분류하고 복구 조치 안내 |
| 주소 수정 시 기존 표시 설정과 일정 보존 필요 | 전용 DB 함수가 캘린더 ID·색상·표시·활성 상태·기존 일정을 보존하며, 주소 변경 시 마지막 수신 시각만 초기화 |
| 수정 전 주소를 다시 추가하면 같은 URL 해시 ID가 기존 구독을 덮어쓸 수 있음 | ID 충돌 시 별도 ID로 새 구독을 등록하고 수정된 기존 구독을 유지 |
| 반복 밀도 사전 검사가 INTERVAL과 BYHOUR의 필터 의미를 무시 | INTERVAL을 반영하고 시간 단위보다 작은 BY 요소만 확장 계수에 반영 |
| 등록 전 상태에 사용 방법 안내가 없음 | **구독 추가 · 관리** 버튼과 Google 로그인 없이 주소를 등록할 수 있다는 안내 |
| 추가/수정 대화상자가 열린 사이 자동 갱신이 시작될 수 있음 | 저장 시 작업 중 여부를 다시 확인하고 겹치는 저장을 차단 |

주소를 수정한 활성 구독은 해당 구독만 즉시 수동 갱신한다. 일시정지한 구독은 수정 후에도 갱신하지 않는다.
중복 주소 검사는 HTTP/HTTPS/webcal 정규화 후 비교하며 주소의 서명된 query 값을 변경하지 않는다.
이전 주소로 시작된 다운로드는 DB 반영 직전 주소 검사로 차단한다. 새 주소의 다운로드·파싱 실패 시 기존 일정은 남는다.

## 사용 경로

1. 캘린더 · 계정 및 동기화 → ICS 구독 → **구독 추가 · 관리**.
2. **ICS 구독 추가**에서 캘린더 이름과 HTTP/HTTPS/webcal 구독 주소 입력.
3. 등록 후 해당 구독만 즉시 갱신. 자동 동기화가 켜져 있으면 기존 1시간 타이머로 갱신.
4. 주소가 바뀌거나 만료되면 전체 캘린더에서 해당 구독을 선택하고 **구독 주소 수정**.
5. 오류가 있으면 **문제 확인**에서 해당 구독을 선택해 상세 원인과 마지막 성공 시각 확인.

- ICS 스냅샷·시간대·공통 조정자·동기화 UI 회귀 검사: **103 passed**, 실패/오류 0.
- 실제 로컬 HTTP 서버 + QThread 워커 + 임시 SQLite DB 통합 검사: **1 passed**.
  첫 가져오기, HTTP 403 시 일정/성공 시각 보존, 200 응답 복구, 일정 ID 유지,
  자동 일시정지 중 자동 실행 차단 및 명시적 수동 실행을 확인했다.
- 19개 번들 언어의 동기화 문구 계약: **19 passed**. 새 ICS 문구 7개를 모든 언어에 추가.
- 인코딩 정책·유틸: **12 passed**. `scripts/run_encoding_guard.py` 최종 실행 성공.
- 마지막 작업 중 저장 차단 변경 후 관련 UI 검사 **6 passed** 재확인.
- 변경 Python 파일 Ruff 검사 및 변경 범위 `git diff --check`: 통과.
- 한국어 Qt 렌더 확인: 아래 화면에서 등록 안내, 접근 거부 안내, 주소 수정 버튼과 스크롤 접근성 확인.

검증은 임시 DB·별도 QSettings와 합성 일정으로 수행했다. 사용자 일정이나 연결 계정을 테스트 데이터로 사용하지 않았다.
기본 샌드박스에서는 loopback 소켓 접근이 거부되어 HTTP 통합 검사가 한 번 실패했다.
같은 검사를 loopback 접근이 허용된 실행에서 재실행해 통과했다.
인코딩 가드는 기본 임시 경로 생성 권한 오류 후 프로젝트 안의 별도 basetemp를 지정해 통과했다.
기존 접근 제한 캐시 디렉터리에 대한 compileall 경고는 남았으나 수정 파일 검사·인코딩 테스트의 종료 코드는 0이다.
