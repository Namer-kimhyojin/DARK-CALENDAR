# Google 설정과 메인 캘린더 개편

2026-10-07 개발 소스의 UI 및 동기화 계약을 개선했습니다. 실제 계정 인증·동기화와 Store 설치판 반영은 별도 단계입니다.

## 사용자 동선

| 작업 | 위치 | 반영 방식 |
|---|---|---|
| 계정 연결·연결 해제 | Google 설정 → 계정 연결 | 기존 비동기 인증·안전한 작업 종료 유지 |
| Google에서 가져올 캘린더 | Google 설정 → 가져올 캘린더 | 읽기 전용 포함, 초안 선택 후 설정 저장 |
| 자동 동기화·주기·시간대 | Google 설정 → 동기화 설정 | 저장 후 적용, 시간대는 고급 설정으로 접음 |
| 새 일정의 기본 저장 위치 | 메인 달력 → 새 일정 저장 | 즉시 저장, 관리 화면에서도 같은 API 사용 |
| 달력과 일정 목록에서 보이기·숨기기 | 메인 달력 → 화면 표시 | 즉시 반영, 여러 항목을 연속 변경 가능 |
| 로컬·ICS 추가·이름·색상 | 메인 달력 → 관리 | 기존 통합 관리 흐름 유지 |

Google 설정의 별도 쓰기 대상 선택을 제거했습니다. 인증·연결 해제는 연결 페이지에서 수행하고 하단에는 저장과 닫기만 남겼습니다. 가져오기 선택, 자동 동기화와 저장 전 상태를 명확히 보여 줍니다.

메인 달력은 현재 기본 저장 캘린더를 바로 보여 줍니다. 숨긴 기본 캘린더에는 `숨김`을 표시하며, 숨김은 저장 대상이나 동기화를 변경하지 않습니다. 기본값을 변경해도 기존 일정은 이동하지 않습니다.

## 저장·동기화 보호

- DB의 명시 기본값과 Google 연결의 과거 설정을 통일하고 Google 계정 `primary`의 실제 identity는 보존했습니다.
- 읽기 전용·비활성·미존재 기본 대상은 거부합니다. 가져오기 선택은 원자 저장하며 기존 기본값이 불가해지면 활성·쓰기 가능한 로컬을 우선합니다. 대체 대상이 없으면 선택 변경을 되돌립니다.
- 가져오기를 꺼도 기존 일정은 보존됩니다. 기존 쓰기 가능한 일정에서 수정한 내용의 Google 전송은 유지됩니다. 화면 표시는 따로 선택합니다.
- 주기적 목록 조회가 해제한 가져오기를 다시 켜지 않도록 보완했습니다.
- 비활성 캘린더의 기존 일정 편집은 소속을 보존합니다. 복사·명시 이동은 선택한 저장 대상과 원본을 구분합니다.
- 기본값 변경은 기존 원격 링크·삭제 대기열을 보존합니다. 아직 Google로 전송하지 않은 일정을 로컬로 이동할 때 과거 Google 경로를 제거했습니다.
- Google 일정 이동이 실패하면 선택한 대상과 재시도 상태를 유지합니다. 이전 캘린더에 저장하거나 다른 캘린더에서 복구해 성공으로 처리하지 않습니다. 원본이 없을 때는 선택한 이동 대상에서만 완료 여부를 확인하고, 확인할 수 없으면 새 사본을 만들지 않습니다.
- Google 이동 성공 후 앱의 연결 정보 저장에 실패한 경우도 재시도 대상으로 유지합니다. 문제 해결 화면에서 이동 실패·이동 확인 필요·이동 연결 저장 필요를 구분하고 같은 대상으로 재시도하는 방법을 안내합니다.
- 실제 Google 이벤트 ID가 없는 로컬·ICS·공유 신규 일정은 오래된 Google 필드로 원격 생성하지 않습니다. 명시한 가져오기 목록을 DB에서 읽지 못하면 해당 동기화를 중단하며 이전 구독으로 우회하지 않습니다.
