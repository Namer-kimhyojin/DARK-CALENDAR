# Google 동기화 날짜 검증 오류 — 2026-10-07

사용자가 보고한 일반 Google 동기화 실패의 직접 원인은 시작과 종료 시각이 같은 시간 일정 1건이었다. 실제 Google 조회는 HTTP 200으로 성공했지만 앱의 `end <= start` 검증이 이 응답을 거부했다. 최신 앱 로그의 `invalid_google_pull_datetime`과 읽기 전용 원격 조회에서 확인한 0길이 일정이 일치한다. 기존 일정과 동기화 토큰을 보존하는 방어 로직 때문에 해당 캘린더의 가져오기가 중단되고 로컬 변경 전송도 보류됐다.

## 확인 근거

- 최신 `crash.log`에서 20:07~20:10의 날짜 검증 실패와 전송 보류를 확인했다. 오래된 `desk_calendar.log`에는 이번 실패가 기록되지 않았다.
- 실제 SQLite를 읽기 전용으로 점검한 결과 `quick_check=ok`, 삭제 대기열 0건이었다. 일정 제목·내용은 조회하지 않았다.
- 활성 Google 캘린더 2개에서 시작·종료·취소 상태만 GET으로 조회했다. 전체 페이지 수신이 완료됐고 344개 항목 중 취소 9개, 정상 종일 265개, 양수 시간 일정 69개, 시작=종료인 시간 일정 1개였다. 역전된 시간·잘못된 날짜는 없었다.
- 수정한 서비스 변환과 전체 스냅샷 검증으로 같은 실제 응답 344개를 다시 읽기 전용으로 확인했으며 실패는 0건이었다. 실제 일정·DB·사용자 설정에 저장하지 않았고 토큰 파일 해시를 유지했다.
- 이 PC에는 Store 3.8.0.0이 설치돼 있고 개발 Python의 `main.py` 실행도 확인했다. 사용자 앱을 종료하거나 재시작하지 않았다. 현재 실행 중인 프로세스에 새 소스가 적용됐다고 주장하지 않는다.

## 수정 내용

- 시간 일정은 종료가 시작보다 앞서는 경우를 거부한다. 시작=종료는 원래 시각의 일정으로 보존하며 임의로 시간을 늘리거나 제외하지 않는다. 수신만으로 원격 생성·수정·중복이 발생하지 않는다.
- 시간 비교에서 소수 초와 실제 UTC 오프셋을 유지하고, 검증 후 기존 DB의 초 단위 형식으로 변환한다. 종일 일정의 종료 제외 날짜, 혼합 형식, 역전된 시간, 불완전 응답의 전체 스냅샷 보호는 유지한다.
- 오프셋 없는 `dateTime`에 명시된 IANA `timeZone`을 적용하고 잘못된 시간대는 거부한다. 이 형식은 [Google 이벤트 API 문서](https://developers.google.com/workspace/calendar/api/v3/reference/events)의 시간대 계약을 따른다. 0길이 일정은 이번 실제 GET 응답에서 관찰한 형태이며 문서의 별도 0길이 보장을 가정하지 않았다.
- 실패 순간의 안전한 오류 코드를 보존해 다른 캘린더의 후속 성공이 앞선 오류를 지우지 않도록 한다. 날짜·DB·HTTP 권한·요청 제한·서버·네트워크 오류를 구분한다. 403 요청 제한은 일반 권한 거부와 구분한다.
- 문제 해결, Google 설정 진단, 수동 실패 팝업에서 같은 원인별 안내를 사용한다. 예외 원문·API 응답·주소·토큰은 사용자 상태 저장과 표시에서 제외한다. 작업 성공 시 오류를 지우고 건너뛴 작업은 기존 오류를 유지한다.
- 보류된 실제 일정 문제와 공급자 오류가 함께 있으면 기존 ‘보류된 항목 확인’ 행동을 유지한다. 새 안내 4개는 한국어·영어 및 나머지 17개 언어의 영어 대체 문자열로 제공한다.

## 검증

관련 검사는 최신 결과와 동일 사례를 중복 제거해 **417개 모두 통과**했다(기능·회귀·번역 405개, 인코딩 정책·유틸리티 12개). 미해결 실패·오류·건너뛴 검사는 없다. 초기 재현 실패와 기존 401 기대값 수정 전 결과도 원본 XML로 보존했다. 전체 저장소 테스트를 완료했다는 의미는 아니다.

새 시간 검사에서는 임시 SQLite에 0길이 일정의 같은 시작·종료, `dirty=0`, 토큰 진행, 기존/신규 수신의 중복 없음과 원격 쓰기 0건을 확인했다. 소수 초, DST, 명시 시간대, 역전·불량 전체 응답과 DB/토큰 보존을 함께 검사했다. 오류 안내에서는 원인 보존·안전 코드·민감정보 비노출·성공/건너뛰기·보류 항목 공존 및 수동 팝업을 확인했다.

Windows 네이티브 Qt의 한국어 어두운 테마 100%·밝은 테마 150%, 620·760px에서 최종 PNG **8개**, UI 조건 **220개**가 통과했다. 실제 클릭·Space 재시도, 작업 중 중복 실행 차단과 원인별 본문을 확인했다. geometry 경고는 없고 개인 QSettings를 보존했다. 제품 7개·테스트 7개 파일의 UTF-8 헤더·컴파일 및 범위 제한 Ruff·diff 검사를 완료했다.

## 적용 범위

개발 소스 수정과 실제 Google 응답의 읽기 전용 해석 검증을 완료했다. 실행 중인 개발 앱은 안전하게 종료 후 재실행해야 변경을 사용한다. 재실행 후 실제 DB 반영·양방향 동기화, 릴리스 빌드·Store 제출·설치판 업데이트는 이번 점검에서 수행하지 않았다.
