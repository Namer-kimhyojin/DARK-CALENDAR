# 날짜·시간 입력 Windows 직접 조작 점검 (2026-10-21)

## 실행 환경과 확인 범위

개발 체크아웃의 실제 `bootstrap.run()`과 `OverlayApp`을 Windows Qt 플랫폼(`QT_QPA_PLATFORM=windows`)으로 실행하고, 네이티브 창에서 마우스와 키보드로 일정·지시/협조·일반업무를 조작했다. 개별 다이얼로그만 흉내 낸 화면이 아니라 실제 메인 창의 등록·수정 경로를 사용했다.

제품 메인 창은 바탕화면 오버레이용 `Qt.Tool | WindowStaysOnBottomHint`를 사용한다. 검증 도구가 정상적인 최상위 창으로 식별하도록 검증 런처에서만 `Qt.Window`와 일반 제목 표시줄 플래그를 지정하고, 제목에 `[검증용 샘플 프로필]`을 붙였다. 초기 창 위치·크기도 지정했다. 해당 플래그와 제목 변경은 제품 코드에 반영하지 않았다.

검증 실행마다 새 샘플 프로필을 생성했다. 일정·일반업무·지시/협조 각 1건을 준비하고, 설정 INI·LOCALAPPDATA·APPDATA·기본 DB·공유 DB·임시/캐시 경로를 프로필 내부로 분리했다. 원본/번들 DB와 자격 증명의 자동 이관을 막고, SQLite의 프로필 외부 접근과 네트워크 연결을 차단했다. 기존 사용자 앱의 단일 인스턴스 잠금 대신 검증 프로필별 잠금을 사용했다.

Windows의 명시적인 `QSettings("조직", "앱")` 생성자는 `setDefaultFormat(IniFormat)`만으로 격리되지 않았다. 런처는 제품 모듈을 가져오기 전에 이 생성자를 명시적인 프로필 INI 파일 기반 생성자로 바꾸고 실제 파일 경로를 확인한다. 이전 자동 검증 런처에도 같은 보완을 적용했다.

## 수정 전 직접 조작

| 화면 | 실제 조작 | 확인 결과 |
|---|---|---|
| 일정 수정 | 시작 `14:00`을 `14:10`으로 변경 | 기존 1시간 길이를 유지하며 종료가 `15:10`으로 변경됨 |
| 일정 수정 | `여러 날`을 켜고 달력에서 종료일을 10월 22일로 선택·저장 | 날짜 범위 선택과 저장 가능 |
| 지시/협조 수정 | `내일`로 10월 22일 선택, 시간 목록에서 `16:30` 선택·저장 | 날짜 빠른 선택과 시간 목록을 함께 사용해 저장 가능 |
| 일반업무 수정 | `내일`로 10월 22일 선택, `09:45` 직접 입력·저장 후 다시 열기 | 정확한 분 값과 날짜가 유지됨 |

직접 조작 중 시간 팝업의 Tab 이동, 빠른 날짜 선택 후 요일 표시, 일정 길이 선택 후 요약 갱신, 지시/협조 바로가기 버튼과 달력 화살표 가독성에 어색한 부분을 확인했다.

## 보완 사항

| 확인한 문제 | 적용한 보완 |
|---|---|
| 시간 목록을 연 상태에서 Tab을 누르면 팝업에 포커스가 남음 | Tab/Shift+Tab으로 팝업을 닫고 다음/이전 입력란으로 이동. 강조된 목록 항목은 확정하지 않음 |
| 시간·날짜 전체 입력과 부분 입력이 혼동되거나 미완료 입력이 뒤늦게 빠른 선택 값을 덮을 수 있음 | 구분자 포함/숫자 입력과 시·분/연·월·일 부분 입력을 구분. 잘못되거나 미완료인 전체 입력은 원래 값으로 복원하고, 외부 값 설정·빠른 선택 시 대기 입력을 비움 |
| 지시/협조 날짜·시간 바로가기 버튼이 비활성처럼 흐리게 보임 | 별도 인라인 스타일을 제거하고 일정·일반업무와 같은 `ghost_btn`/`quickActionButton` 공통 스타일 적용. 글자가 잘리지 않도록 고정 폭 대신 최소 폭 사용 |
| 어두운 달력의 이전·다음 달 화살표가 거의 검게 보임 | 팝업 공통 처리에서 표준 Qt 아이콘을 공통 아이콘으로 바꾸고 현재 테마의 `text_primary` 색 적용 |
| 일반업무에서 빠른 날짜 선택 후 요일 배지가 이전 값으로 남음 | 빠른 선택 뒤 날짜와 요일 표시를 함께 갱신 |
| `2시간` 등 일정 길이 선택 뒤 요약이 이전 길이를 표시함 | 종료 일시와 일정 요약을 함께 갱신 |

## 수정 후 Windows 직접 조작

- 시작 `14:00`에서 시간 팝업을 열고 `14:30`을 강조한 뒤 Tab을 눌렀다. 팝업이 닫히며 시작값은 `14:00`으로 유지되고 종료 `15:00` 입력란으로 포커스가 이동했다.
- 분 영역을 클릭하고 숫자 키패드 `5`를 입력해 `15:05`로 변경되는 것을 확인했다.
- 시작 `23:45`에서 `2시간`을 선택해 다음 날 `01:45`가 되는 것을 확인하고 저장했다.
- 지시/협조의 날짜·시간 바로가기 버튼이 활성 버튼으로 명확히 보이며, 어두운 팝업 달력의 이전·다음 달 화살표도 밝게 표시되는 것을 실제 화면에서 확인했다.

- 최종 수정본을 다시 실행하고 새 일정에서 시작 `09:00`에 `2시간`을 선택했다. 종료가 `11:00`으로 바뀌면서 요약도 즉시 `2시간`으로 갱신되었고, 등록 완료와 메인 화면 반영을 확인했다.
- 일반업무에서 `내일`을 눌러 날짜가 `2026-10-22`, 요일 배지가 `목`으로 함께 바뀌는 것을 확인했다. 시간 목록에서 `14:30`을 선택하고 저장 완료 및 메인 화면의 `~10.22` 반영까지 확인했다.

## 자동 검증과 근거

- 새 키보드 입력 회귀 33개: 구분자 포함/숫자 입력, 잘못된 값·미완료 입력 복원, 날짜·시간 부분 입력, 팝업 Tab/Shift+Tab 이동, 외부 setter와 빠른 선택 후 입력 상태 처리.
- 관련 집중 검사 100개와 하위 검사 8개 통과. XML의 전체 집계는 108이며 실패·오류·건너뜀은 0이다. 기존 공통 편집기 스타일 검사 16개도 통과했다. 서로 중복되는 재실행 결과를 합산하지 않는다.
- 지시/협조·공통 스타일 수정 후 관련 검사 22개를 재실행해 통과했다. 이 수치는 위 흐름과 중복되는 별도 재확인이다.
- 최종 인코딩 가드(전체 Python 컴파일, 인코딩 정책·유틸리티 검사), 수정 Python 파일 7개의 Ruff 검사와 포맷 검사, `git diff --check`를 통과했다.
- 생성·수정·이동·복사와 종일·정확한 분·반복 메타데이터 보존은 기존 저장 경로를 사용하는 격리 SQLite 검사로 확인했다. 이번 네이티브 마우스 조작만으로 모든 이동·복사 경로를 확인했다고 보지는 않는다.

## 남는 확인 범위

이번 결과는 개발 소스를 실행한 격리 Windows 앱과 자동 회귀 검사 기준이다. 설치된 Store 앱, 새 패키지 빌드·배포, 실제 외부 계정 동기화, 모든 Windows 배율 조합은 검증하지 않았다. 제품 버전은 올리지 않고 변경 이력만 등록한다. 기존 작업의 [입력 개선 기록](schedule-datetime-input-20261021.md)과 구분해 읽는다.
