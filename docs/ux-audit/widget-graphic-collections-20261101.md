# 위젯 그래픽 컬렉션 — 2026-11-01

8종 오버레이 위젯의 숫자·재질·배치를 함께 바꾸는 선택 기능을 추가했다. 새 위젯의 기존 Pure Type·글자 그림자 기본값과 저장된 사용자 디자인은 그대로 유지한다. 이번 변경은 현재 개발 소스에 반영되며, 기존 공개 패키지·설치본·Store 상태는 이번 작업에서 변경하지 않았다.

## 사용 방법

1. 위젯을 오른쪽 클릭하고 **그래픽 컬렉션**을 선택한다. KeyDeck도 같은 메뉴를 제공한다.
2. 실제 위젯 렌더러로 그린 미리보기에서 컬렉션을 고른다.
3. **상태 변화 애니메이션**, **글자 대비 자동 보정**을 필요에 맞게 선택한다.
4. 기본 적용 범위는 **이 위젯에 적용**이다. 여러 위젯을 맞추려면 **표시 중인 위젯 전체에 적용**을 선택한다. 숨겨진 인스턴스는 바꾸지 않는다.
5. **적용**을 누른다. **취소**와 미리보기 탐색은 원본 위젯 설정을 쓰지 않는다.

**기존 디자인 · 개별 설정 유지**를 적용하면 컬렉션이 바꾼 외관을 이전 값으로 복원한다. 컬렉션 적용 후 사용자가 직접 바꾼 색상 등의 값은 현재 값이 컬렉션 적용값과 같을 때만 복원하므로 이후 편집을 되돌리지 않는다. 별도 표시 형식이나 날씨/KeyDeck 전용 디자인을 명시적으로 선택하면 그 선택을 우선한다.

## 세 가지 컬렉션

| 컬렉션 | 화면 구성 |

| Pure Air | 투명 표면, 큰 숫자, 절제한 보조 정보, 기존 글자 그림자 설정 반영 |
| Soft Object | 밝고 둥근 표면, 날짜·D-Day의 기존 입체 그림, 정돈된 제목과 본문 |

## 유형별 변경

- 시계: 자리 폭을 고정해 숫자가 바뀔 때 위치가 흔들리는 현상을 줄이고 초를 작게 구분한다. 계기판형에서는 시침·분침·초침을 함께 표시한다.
- 날짜·D-Day: 큰 날짜/남은 일수, 제목·목표 날짜의 위계를 구분한다. 밝은 컬렉션은 기존 계절·기념일 그림 팩을 사용한다.
- 스톱워치: 작은 소수 표시와 실행/정지 상태 점을 제공한다. 기본 HTML 템플릿에서 마지막 숫자가 잘리던 줄바꿈 측정도 바로잡고, 사용자 템플릿의 줄바꿈은 유지한다. 반복 외관 갱신 시 스타일 문자열을 계속 덧붙이던 부분을 정리했다.
- 카운트다운: 초를 작게 표시하고 마지막 60초를 강조한다. 시작 길이와 목표의 대응 관계가 확인된 경우에만 진행 원호를 표시한다. 이전 목표에 임의의 진행률을 만들어 넣지 않는다.
- 텍스트: 첫 줄을 제목, 나머지를 본문으로 표현한다. 기존 정렬·자동 줄바꿈·템플릿 갱신 설정을 따른다. 글꼴·원문은 보존하며 컬렉션 화면에서는 서식 HTML을 일반 텍스트로 표시한다.
- 날씨: 기존 내장 움직임·사용자 WebP/GIF·예보를 재사용한다. 그림자를 켰을 때 글자색을 덮어쓰던 오류와 밝은 배경의 과도한 그림자를 보완하고, 전경/배경 대비를 선택적으로 보정한다.
- KeyDeck: 케이스·키캡·조명 색상을 맞춘다. 키 동작·라벨·프로필·재질·배치·크기·개인 그림을 보존한다. 비트메이커의 사운드 키 의미 색상도 보존한다.

## 움직임·성능·호환성

일반 위젯은 실행/정지·완료 상태가 바뀔 때만 180ms 전환을 사용한다. 숨김·비활성화·움직임 끔에서는 전환을 중단한다. Windows 애니메이션 정책을 존중하며, 날씨는 기존 절전·숨김 중단 정책을 유지한다. 일반 위젯에 상시 애니메이션 타이머를 추가하지 않는다.

배경과 내용 레이어를 나누어 캐시하며 내용이 바뀔 때 해당 레이어를 다시 그린다. 입체 그림은 배율을 고려한 크기로 캐시하며 항목 수·최대 해상도를 제한한다. 크기가 작아지면 보조 장식·설명을 줄이고 주요 숫자를 우선한다. 원본 전체 정보는 접근성 이름과 도움말에도 제공한다. 실제 CPU·배터리 절감률은 이번 검증에서 측정하지 않았다.

설정은 기존 인스턴스 `oi_<inst_id>_` 공간 안에서 관리한다. 새 애플리케이션 전역 상태·DB 스키마·외부 의존성은 추가하지 않는다. 사용자 글꼴 이름·폰트 크기·전체 불투명도·목표·원문·위치를 보존한다. 저장한 컬렉션은 재시작 시 복원한다.

## 검증 및 한계

- 새 회귀 `tests/test_widget_graphic_collections.py`: 37건. 6종 일반 위젯 × 3컬렉션 × 3크기 렌더링, 7종 재시작, 원복·개별 편집 보존·숨김 제외·KeyDeck 동작 보존·전환 중단·날씨 대비 등을 확인했다.
- 확대 회귀 최종 결과: **37개 파일, 1,341건, 실패·오류·건너뜀 0건**, 모든 파일의 프로세스 종료 코드 0. Qt 테스트 파일마다 별도 프로세스·임시 INI·임시 LOCALAPPDATA로 실행했다. 결과는 `artifacts/widget-graphics-20261101/regressions-final/results.json`과 각 파일의 JUnit XML·로그에 보관한다. 종료 코드도 함께 확인하며 XML 합계만으로 전체 성공을 판단하지 않는다.
- 초기 검사에서는 글꼴을 제공하지 않은 offscreen 플랫폼의 글리프/썸네일 실패가 있었다. Windows 글꼴을 명시적으로 로드해 검증했다. 네이티브 Windows 배치 비율 4건의 실패는 변경 전 HEAD의 격리 사본에서도 같은 값으로 재현되었다. 실제 화면 검증과 자동 기하 테스트의 플랫폼을 구분한다.
- 날씨 로딩 회귀에서는 이전 테스트의 Qt 창을 닫기만 하고 삭제하지 않아 메뉴 생성 시 간헐적으로 프로세스가 종료되었다. 테스트 경계에서 창·부모의 `deleteLater()`와 DeferredDelete 전달을 명시한 뒤 전체 로딩 검사를 다시 확인했다. 제품의 위젯 삭제 흐름도 기존에 `deleteLater()`를 사용한다.
- `scripts/validate_widget_graphic_collections.py`: 8종 × 3컬렉션 실제 소스 렌더링, 160/320/480 너비, 선택 대화상자. Windows 100/125/150/200% DPR에서 캡처했다. 각 결과에서 실제 사용자 QSettings 보존, 날씨 네트워크 요청 0건을 확인했다.
- Python 인코딩 가드·Ruff·변경 이력 누락 검사를 실행한다. 라이브 날씨 공급자 응답·실제 설치본·Store 패키지·장시간 배터리 사용은 이번 작업의 검증 범위에 포함하지 않는다.

핵심 파일: `widget_graphics.py`(렌더러), `widget_graphic_runtime.py`(인스턴스 연결·복원), `widget_graphic_dialog.py`(미리보기·선택). 나머지 기존 위젯은 해당 유형의 갱신 지점에서 이 기능에 연결한다.
