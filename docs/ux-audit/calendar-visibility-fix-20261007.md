# 캘린더 숨김과 일정 출처 점검 — 2026-10-07

## 첨부 화면의 데이터 확인

로컬 앱 데이터 DB를 읽기 전용으로 확인했다. 이차전지산업팀은 `is_visible=0`, `is_active=1`, `is_default=1`이며,
연결된 35개 원격 미러는 모두 정확한 팀 캘린더 ID를 갖고 있었다.

2026-10-09의 ‘한글날’ 두 항목은 이 팀에 속하지 않았다.

| 항목 | 저장된 소속과 상태 |
|---|---|
| 로컬 일정 | 소속 캘린더 없음, Google 연결 없음, `local_owned` |
| Google 공휴일 | 대한민국의 휴일, 화면 표시 켜짐, 가져오기 선택 꺼짐, `remote_mirror` |

팀 표시를 꺼도 다른 출처의 항목은 표시된다. 가져오기 선택을 끄는 것은 저장된 일정을 숨기는 설정과 독립이다.
위 기록의 소속을 추정하여 바꾸거나 일정·구독을 삭제하지 않았다.

## 발견한 예외와 개선

격리된 DB에서는 과거 Google 원본 ID만 남은 일정 및 원격 미러에 잘못된 로컬 ID가 남은 일정이 숨김 설정을 우회했다.
일별 조회는 기본 별칭을 처리하지 못하고, 기간 조회는 SQL에서 별칭을 먼저 숨겨 실제 소속의 표시 상태와 다른 결과를 만들기도 했다.

- 순수 `CalendarVisibility` 정책으로 소속을 판정한다. Google 원격 미러의 실제 원본·대상 ID를 우선하고, 기본 별칭을 해결한다.
- `local_owned`는 현재 저장된 소속을 유지한다. 일정 이동 직후 남아 있는 이전 Google 원본이나 전송 대상이 로컬 소속을 바꾸지 않는다.
- 일별·기간·일반업무 화면 조회에 같은 표시 정책을 적용한다. 관리용 원본 조회와 저장된 일정은 유지한다.
- 월간·날짜형 주간·시간표와 위젯용 데이터에도 같은 정책을 적용한다. 기본 저장 대상과 가져오기 활성 상태는 표시 여부와 분리한다.
- 마우스를 올린 일정에 소속 캘린더 이름을 표시한다. 같은 제목의 서로 다른 공휴일을 구분할 수 있다.
- 캘린더 이름과 제목에 `<`, `&`가 있어도 시간표 안내에서 문자 그대로 표시한다.

## 검증

세 XML 보고서의 검사 ID를 합쳐 **중복을 제외한 관련 검사 203개**, 별도 인코딩 검사 12개가 통과했다.
실패·오류·건너뜀은 없다. 기존 테스트 클래스를 가져온 통합 검사의 중복 실행은 검사 수에 중복 산입하지 않았다.
순수 정책·화면용 DB 조회·실제 체크박스 ON/OFF·월간/날짜형 주간/시간표·시간/종일·위젯 캐시·기본 저장 대상·문자 이스케이프를 포함한다.
수정 범위 Ruff·diff 검사와 compileall·인코딩 가드를 통과했다.

실제 Windows Qt에서 어두운·밝은 테마를 확인했다. 샘플 팀 일정 표시를 끄면 전체 3개에서 팀 일정이 빠져 2개가 남고,
위젯 데이터도 3개→2개로 갱신된다. 두 공휴일의 실제 툴팁은 각각 ‘로컬’과 ‘대한민국의 휴일’을 표시한다.
샘플 일정의 모든 저장 컬럼과 실제 사용자 설정이 유지됨을 확인했다.
