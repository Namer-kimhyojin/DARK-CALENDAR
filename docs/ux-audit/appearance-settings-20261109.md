# 모양 설정·세부 모양 조정 점검과 개선 (2026-11-09)

사용자 보고: 스타일(시스템 기본·라이트·다크) 전환 시 화면 깨짐과 지연, "모든 스타일 보기" 중복, 푸터 위 구분선 중복, 세부 모양 조정의 보이지 않는 글자와 통일감, 그림자의 다크/라이트 구분, 창 모서리 둥글림.

## 측정과 원인

실제 Windows 렌더링 백엔드에서 `_set_appearance_mode`를 호출해 측정했다. 이 PC의 Qt는 프로세스에서 처음 글꼴 크기를 잴 때 글꼴 DB 초기화에 약 47~59초가 걸리지만, 앱 로그의 시작 시간(약 3.5초)과 맞지 않는 측정 환경 특성이라 제외하고 글꼴을 미리 데운 뒤 쟀다.

| 전환 | 수정 전 | 수정 후 |
|---|---|---|
| 라이트·다크 | 약 90~100ms | 약 110ms (한 번만 그림) |
| 시스템 기본 | **약 4,600ms** | **약 120ms** |

- **시스템 기본 지연:** `_effective_appearance_mode()`가 한 번의 전환에 493회 호출되고, 시스템 모드일 때마다 `_system_mode_variant()`가 테마 스냅샷 전체를 만들었다. 스냅샷 하나가 모든 대화상자 지표를 `QSettings`(레지스트리)에서 읽어 `QSettings.value`가 67,641회(4.3초) 호출됐다. "auto"는 운영체제 색 체계 조회(`resolve_system_text_theme()`)와 같은 값이라 직접 조회로 바꿨다.
- **화면 깨짐:** 한 번의 클릭이 여러 단계로 나뉘어 반쯤 칠해진 프레임이 그려졌다. 스타일 카드 9개는 두 번씩 다시 칠했고, 같은 값의 `setStyleSheet`도 다시 폴리시했다. 전환 전체를 `_batched_updates()`로 묶어 한 번만 그리고, 같은 값은 건너뛰며(`_set_style`), 중복 호출을 제거했다.

## 수정

1. **모든 스타일 보기 제거:** 체크박스·프리셋 종류 필터·프리셋 격자·자동 적용 체크박스와 이 갤러리 전용 상태·메서드를 제거했다. 구성은 모드 3개 + 스타일 카드 9개(기본)와 직접 색상이다. 스타일 선택은 항상 권장 글자색을 함께 적용한다(기존 기본 동작).
2. **구분선 중복:** 푸터 프레임의 `role="dialogFooter"`가 위쪽 테두리를 그리고, 바로 위에 `HLine`을 따로 추가해 두 줄이었다. role을 제거했다.
3. **창 모서리:** 그림자 창만 둥글고 실제 창은 직각이었다. 그림자 컨트롤러가 창에 둥근 마스크(사각형 2개 + 모서리 타원 4개)를 적용하고, 그림자도 같은 곡선으로 잘라 모서리 바깥을 채운다. 최대화·전체 화면에서는 마스크를 푼다. 반지름은 `group_radius`(최대 20).
4. **그림자 라이트/다크 구분:** 라이트는 푸른 슬레이트 색조에 완만하고 넓은 번짐(가장자리 3px 알파 약 105, 20px에서 약 17), 다크는 순수 검정에 더 깊고 빠르게 줄어듦(약 190, 약 9)과 밝은 테두리선이다. 이전에는 둘 다 거의 같은 near-black이었다.
5. **헤더·그림자가 대화상자의 테마를 따름:** 헤더와 그림자는 저장된 설정으로만 색을 계산해, 모양 설정에서 다크를 미리보기하는 동안 열린 세부 모양 조정은 흰 헤더 위에 밝은 제목 글자(보이지 않음)가 됐다. `apply_common_dialog_style`이 받은 테마를 기억(`_dc_theme_args`)해 헤더·그림자가 같은 값을 쓴다.
6. **파일 메뉴:** 운영체제 색 체계의 어두운 메뉴 배경에 대화상자의 글자색이 겹쳐 글자가 사라졌다. 대화상자 토큰으로 만든 메뉴 스타일(`build_dialog_menu_stylesheet`)을 적용했다. 글꼴 패밀리는 Pretendard로 측정했을 때 메뉴를 비워도 같았으므로, 보였던 차이는 글꼴 종류가 아니라 가독성이었다.
7. **미리보기:** ① 선택한 날짜 글자색이 `accent_text`가 없어 흰색으로 대체돼 연한 포인트색에서 대비가 1.1:1(26개 조합 중 22개가 기준 미달)이었다. `contrasting_text_color`로 고정했다. ② 미리보기 글꼴이 대화상자의 초안이 아니라 전역 저장 글꼴을 읽어 둘이 다르면 넘쳤다. 대화상자의 글자 크기 단계를 쓰도록 했다.
8. **영어 문구:** 프리셋 이름 4개와 설명 17개가 영어 코드 문자열이 그대로 표시됐다. 내부 키는 두고 표시만 번역한다. ko·en은 번역하고 나머지 17개 로케일은 영어를 넣었다(원어민 감수 대상).

## 글꼴 적용 점검 (같은 날 추가)

"모달창에 글꼴이 적용되지 않은 곳이 있다"는 보고를 측정으로 확인했다.

- **위젯 글꼴은 일관됨:** 앱과 같은 설정(`build_ui_font` + 메인 창 전체 스타일시트, Pretendard)으로 세부 모양 조정·모양 설정·도움말 센터·메시지 상자·입력 상자를 열고, 모든 탭·접힌 섹션·숨은 페이지까지 포함한 1,613개 위젯의 글꼴을 측정했다. 전부 같은 패밀리였다. 위젯 종류별 측정(라벨·입력·표 머리글·콤보 팝업·메뉴·툴팁·메시지 상자 등 30종)도 마찬가지였다.
- **실제로 글꼴을 무시한 곳:** 사용자가 고른 글꼴 대신 고정 목록을 쓰던 5곳을 앱 글꼴을 따르게 했다. 명령 팔레트의 검색창(같은 팔레트의 목록은 앱 글꼴이라 한 창 안에서 갈렸다), 호버 정보 카드, 잠금 화면 시계, 집중 모드 타이머 2곳, 드래그 미리보기 카드 3곳(맑은 고딕 고정).
- **의도된 고정 글꼴(변경 없음):** 자리비움 설정의 HTML 소스 편집창(고정폭), 스플래시, 인쇄, 바탕화면 위젯의 표시 프리셋과 그래픽.
- 새 테스트 `test_ui_follows_app_font.py`가 `presentation` 아래에서 글꼴 패밀리를 직접 적은 코드를 찾아, 위 의도된 목록 밖에 새로 생기면 실패한다.

## 전체 글꼴 하드코딩 점검 (같은 날 추가)

`calendar_app` 전체의 고정 글꼴 이름(약 80곳)을 분류했다. 기준은 "사용자가 고른 글꼴을 무시하고 보이는 글자가 고정되는가"이다.

- **고침 (사용자 설정을 무시하던 곳):**
  - 인쇄 글꼴(`calendar_print_renderer`)이 맑은 고딕으로 고정. 이제 설정 글꼴로 인쇄되며 PDF에 해당 글꼴이 임베드됨을 실제 Windows에서 확인했다.
  - 가로 전환 미리보기 시계(`overlay_shadow`)가 맑은 고딕 고정이었다. 앱 글꼴로 바꿨다.
  - 메뉴 스타일 2곳(`infra_wiring`, `overlay_base`)이 글꼴 패밀리를 고정해 메뉴가 앱 글꼴을 따르지 않았다. 고정을 없애 상속하게 했다. 이모지는 Qt가 글리프 단위로 대체하므로 영향이 없다.
  - 단축키 도움말 본문(`keyboard_shortcuts`)이 맑은 고딕 고정이었다. 상속하도록 바꿨다. 키캡의 고정폭은 유지.
- **유지 (의도된 설계):**
  - 설정 없을 때의 기본값(`bootstrap`, 날씨·그래픽의 `family` 기본 인자 — 호출부가 설정 글꼴을 넘김).
  - 프리셋 후보 목록(`overlay_display_presets`) — 설치된 첫 글꼴을 고름.
  - 폴백 목록(`overlay_base._FONT_FALLBACKS`) — 저장된 글꼴이 설치되지 않았을 때만 사용.
  - 고정폭 — 키캡, HTML 소스 편집창.
  - 스플래시 — 설정 글꼴이 적용되기 전에 그려짐(`bootstrap`에서 스플래시가 먼저 생성됨).
- **가드:** `tests/test_ui_follows_app_font.py`가 위 허용 목록 밖의 고정 글꼴을 찾아 실패시킨다. 고정을 되돌리면 해당 파일을 지목하며 실패함을 확인했다.

부수 수정: 16개 로케일 + `en/ko/ja`의 `loop_mixer` 키 순서가 캐논 정렬과 달라 i18n 캐논 테스트가 실패하던 것을, 값 변경 없이 정렬만 바로잡았다(내용 동일성을 검사한 뒤 저장).

## 검증

- 새 회귀 테스트: 그림자 라이트/다크 차이, 창 마스크 4모서리·최대화 해제, 둥근 영역 모양, 헤더·그림자가 대화상자 테마를 따름(양방향), 푸터 구분선 1줄, 미리보기 글자 대비(26개 조합), 프리셋 표시 번역과 키 선택. 수정을 되돌리면 실패함을 각각 확인했다.
- 실제 화면 캡처(항상 위 + 중립 배경, 모서리 확대)로 창이 둥글게 잘리고 곡선을 따라 그림자와 테두리선이 이어지는 것을 확인했다.
- 화면에 의존하지 않는 합성 렌더링(대화상자 `grab()` + 둥근 마스크 + 그림자 창 `render()`)으로 라이트·다크·편집기를 확인했다.

## 남은 것

- 17개 로케일의 프리셋 문구는 영어다. 원어민 감수 때 번역한다.
- 라이트·다크 전환은 약 110ms로, 남은 비용 대부분은 Qt의 스타일시트 재폴리시(전체 대화상자 29ms, 섹션 프레임 약 24ms)다. 더 줄이려면 섹션별 스타일을 대화상자 공통 스타일로 합쳐야 한다.
- 이 PC의 전역 설정에 `font_size = 24`가 저장돼 있다. 테스트 중 남은 값인지 사용자가 직접 정한 값인지 확인되지 않아 건드리지 않았다.
