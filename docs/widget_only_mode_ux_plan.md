# 위젯 전용 모드 UI/UX 개선 계획

> 작성: 2026-10-01 · 상태: B·C·D 로컬 구현 및 자동·샘플 검증 완료, 실제 환경 인수 확인 대기
> 범위: 일정·업무·지시·협조를 보여 주는 통합 위젯 창. 시계·날씨·KeyDeck 등 개별 오버레이 위젯의 재설계는 별도 범위입니다.

구현 결과와 검증 범위: [widget_only_mode_ux_results.md](widget_only_mode_ux_results.md). 아래 표는 최초 계획과 당시 관측을 보존합니다.

## 1. 목표와 기준

작은 데스크톱 창에서 사용자가 선택 날짜와 필터를 즉시 이해하고, 항목을 읽고 추가·완료·수정한 뒤에도 작업 맥락을 유지하도록 개선합니다.

- 주요 흐름: 날짜 확인 → 유형 선택 → 항목 읽기 → 추가 또는 처리 → 결과 확인.
- 기본 레이아웃·스킨·밀도·기존 사용자 설정을 유지합니다. 새 레이아웃 추가보다 기존 사용 흐름의 개선을 우선합니다.
- [AGENTS.md](../AGENTS.md), [위젯 규칙](../rules/overlay_widgets.md), [UI 지침](../rules/dialog_ui.md), [테마 계약](../rules/theme_token_completion_process.md), [i18n 규칙](../rules/i18n.md)을 적용합니다.
- 계획의 제안은 구현 완료를 뜻하지 않습니다. 기존 수동 검증 대기 상태와 미커밋 변경을 보존합니다.

## 2. 확인 방법과 한계

현재 `unified_widget_mode.py`, `widget_mode_coordinator.py`, 꾸미기 다이얼로그와 관련 회귀 테스트를 읽었습니다. `tests/test_widget_mode_ux.py`의 Host를 사용하여 Windows Qt 플랫폼에서 현재 창을 렌더링했습니다. 테스트 전용 메모리 설정과 샘플 일정·업무·지시 각 1개를 사용했으며 실제 사용자 DB나 설정은 변경하지 않았습니다.

| 실제 창 크기 | 목록 뷰포트 | 필터 배치 |
|---|---|---|
| 360 × 560 | 330 × 335 | 현재 선택값을 표시하는 메뉴 |
| 420 × 520 | 390 × 268 | 필터와 실행 버튼 두 줄 |
| 760 × 600 | 730 × 345 | 한 줄 |

목록 뷰포트는 해당 샘플·기본 설정에서의 측정값입니다. 다른 스킨·배치·글꼴에서도 같은 값을 보장하지 않습니다. 실제 사용자 데이터, 장시간 사용, 다중 모니터·DPI, 스크린 리더, 현재 Store 설치본은 검증하지 않았습니다. 전체 회귀 테스트를 이번 계획 작업에서 실행하지 않았습니다.

## 3. 이미 구현된 기능 — 유지할 계약

| 영역 | 확인된 현재 동작 |
|---|---|
| 진입·복귀 | Coordinator를 통해 메인 창과 위젯 창의 표시 상태 관리, 메인 복귀·트레이 숨김·화면 내 위치 복구 제공 |
| 날짜 | 날짜 선택·오늘 이동, 주간/월간 캘린더, 레이아웃별 접기 상태 및 크기 복원 |
| 필터 | 전체·일정·업무·지시 구분, 좁은 폭에서 두 줄 또는 메뉴형 전환, 선택 필터 저장 |
| 추가 | 선택 유형별 기존 다이얼로그 연결, 전체에서는 유형 선택 메뉴, 선택 날짜 전달 |
| 처리 | 항목 열기·완료·우선순위·삭제 메뉴, 읽기 전용 구독 일정 변경 제한 |
| 완료 복구 | 성공 후 상태 반영, 실패 시 원래 데이터 재렌더링, 최근 완료 변경 1건 실행 취소 |
| 데이터 상태 | 로딩·지연·빈 목록 구분, 지연 시 재시도, 이미 받은 데이터 유지 |
| 꾸미기 | 레이아웃·색상·밀도·글꼴·불투명도 설정, 초안 미리보기와 적용/취소 |
| 목록 효율 | 동일 렌더 키일 때 재생성 생략, 데이터 캐시, 숨김 시 갱신 제한 |

위 항목을 신규 개발로 다시 계획하지 않습니다. 기존 테스트가 있는 기능도 새 변경 후 회귀 검증합니다.

## 4. 개선 과제와 우선순위

| 우선순위 | 근거 또는 불확실성 | 제안 | 완료 기준 |
|---|---|---|---|
| P1 | 화면의 `주간`/`월간` 버튼은 보기 기간 전환처럼 읽히지만 `_toggle_week()`는 달력 영역 노출을 전환함 | `달력 접기` / `달력 펼치기`로 동작을 명시하고 체크 상태·접근성 설명 일치 | 주간/월간·펼침/접힘 조합에서 라벨과 실제 동작 일치 |
| P1 | 360px 필터는 의미가 유지됨. 상단 복귀·고정·꾸미기와 행 더 보기 아이콘은 처음 쓰는 사람에게 발견성 검증 필요 | 좁은 창의 아이콘은 유지하되 포커스·도움말 강화. 충분한 폭에서는 복귀·꾸미기 라벨 표시 | 필터 의미 손실 없이 키보드만으로 메인 복귀·설정 접근 가능 |
| P1 | `update_agenda()`는 변경 시 `_clear_items()`로 목록을 교체함. 항목 단위 스크롤·포커스 복원은 해당 경로에서 확인되지 않음 | 동일 날짜·필터의 갱신은 `(source, item_id)` 앵커와 화면 내 오프셋으로 읽던 위치 복원 | 목록 중간에서 완료·외부 갱신 후 이웃 항목으로 자연스럽게 연결 |
| P1 | 실행 취소는 1건이고 8초 뒤 feedback 및 undo 상태를 지움. 실패 복구는 이미 있음 | 결과에 항목명 포함, 목록이 사라져도 성공·실행 취소 발견 가능. 명시적 포커스가 있는 동안 버튼을 자동 제거하지 않음 | 완료→실행 취소→재완료와 실패 재시도 모두 문맥·포커스 보존 |
| P2 | 선택 날짜가 짧게 표시되고 항목 수는 `3개` 또는 비율로 표시됨. 필터/완료 포함/기한 경과를 함께 이해하는지 검증 필요 | 날짜·현재 유형·완료 포함 상태를 명확하게 연결. 숫자의 의미는 도움말·접근성 설명으로 보완 | 화면만 보고 선택 날짜·유형·완료 포함 여부 식별 |
| P2 | 그룹·기한 경과·기한 없음·완료 배지는 이미 있음 | 기존 그룹 안에서 제목→시간/마감→보조정보 위계를 정돈하고 긴 제목 규칙 통일 | 긴 제목·다국어에서도 시간과 빠른 메뉴가 겹치지 않음 |
| P2 | 빈 목록에 추가 동작, 지연에 재시도는 이미 있음 | `이 날짜에는 없음`, `이 유형만 없음`, `불러오기 지연`의 설명·복구 버튼을 일관되게 정돈 | 필터만 바꾸면 항목이 있는 상태를 데이터 없음으로 오해하지 않음 |
| P2 | 더 보기 메뉴에 밀도·기간·관리·배치·스킨·복귀·트레이 동작 혼재 | 날짜 이동 / 업무 관리 / 보기 설정 / 창 관리 순으로 그룹화. 꾸미기와 같은 설정에는 같은 이름 사용 | 기존 기능 전부 접근 가능, 설정 중복이 서로 다른 상태를 만들지 않음 |
| P3 | 행 위젯 재생성 비용은 존재하나 대량 데이터 성능은 미측정 | 먼저 데이터량별 비용 측정. 필요할 때 변경 행 갱신 또는 모델 기반 목록 검토 | 대표 데이터에서 정한 성능 기준을 만족하고 UI 멈춤 없음 |

P1은 의미·흐름 안정성, P2는 정보 위계·발견성, P3는 측정 결과에 따른 확장입니다. 기능을 늘리는 것보다 P1을 먼저 완료합니다.

## 5. 목표 화면과 상호작용

### 정보 배치

1. 상단: 메인 복귀, 선택 날짜, 오늘, 항상 위, 꾸미기, 더 보기.
2. 날짜 영역: 현재 레이아웃의 주간 또는 월간 달력. 접기/펼치기 동작을 명시.
3. 작업 영역: 유형 필터와 주요 추가 동작. 넓은 폭은 한 줄, 좁으면 두 줄, 더 좁으면 현재 값이 보이는 메뉴.
4. 목록: 유형/기한 그룹 → 항목 제목 → 시간·마감 → 상태. 목록 읽기가 꾸미기보다 먼저 보이도록 유지.
5. 하단: 완료 포함, 처리 결과·실행 취소, 항목 수·시계. 창이 낮으면 피드백이 목록 전체를 밀어내지 않도록 별도 공간을 제한.

필터·주요 추가·달력 노출 라벨을 말줄임표나 한 글자·툴팁만으로 대체하지 않습니다. 긴 작업 제목은 2줄까지 읽을 수 있는 배치를 우선 검토하고, compact 밀도는 1줄 생략과 전체 제목 도움말을 유지하는 안을 비교합니다. 실제 번역 문자열과 폰트 측정으로 반응형 전환 폭을 정합니다.

### 흐름별 계약

| 흐름 | 목표 동작 |
|---|---|
| 전체에서 추가 | 유형 메뉴 → 선택 날짜가 들어간 기존 다이얼로그 → 저장 후 같은 창·필터로 복귀 |
| 일정·업무·지시에서 추가 | 해당 유형 다이얼로그 직접 열기. 기존 route·create/move/copy·calendar_id 계약 유지 |
| 완료 | 저장 성공 → 항목명 포함 피드백 → 완료 포함이 꺼져 있으면 다음 읽을 항목으로 포커스 이동 |
| 저장 실패 | 기존 상태 복원 → 원래 항목 포커스 유지 → 재시도 가능한 실패 설명 |
| 실행 취소 | 직전 상태 복원. 이전 상태가 in_progress이면 pending으로 단순화하지 않음 |
| 데이터만 갱신 | 같은 날짜·필터에서는 읽던 항목 유지. 앵커 삭제 시 다음 항목, 없으면 이전 항목 |
| 날짜·필터 변경 | 목록 처음으로 이동하는 규칙을 명시. 과거 스크롤 위치가 새 문맥에 끼어들지 않음 |
| 꾸미기 취소 | 프리뷰 변경을 사용자 설정에 저장하지 않음. 스킨·배치·밀도 독립성 유지 |
| 메인 복귀·트레이 | 사용자에게 복귀와 숨김을 구분해 안내하고 Coordinator의 재개/종료 계약 유지 |

실행 취소는 이번 단계에서 최근 1건 계약을 유지합니다. 다단계 기록과 삭제 복구는 데이터 정책 검토가 필요한 후속 범위입니다. 스크린 리더에서는 피드백을 알리되 창을 강제로 활성화하지 않습니다.

### 키보드·접근성

- Tab 순서: 날짜·창 동작 → 달력 → 필터 → 추가 → 목록 → 완료 포함·복구.
- Enter는 항목 열기, Space는 완료 체크의 기존 네이티브 동작 유지.
- 항목 메뉴는 키보드로 열 수 있도록 검증하고, 숨겨진 레이아웃 컨트롤을 포커스 순서에서 제외.
- 새 전역 단축키는 추가하지 않습니다. 로컬 단축키는 기존 설정과 충돌 여부를 확인한 뒤 결정.
- 읽기 전용 상태는 색상뿐 아니라 텍스트/접근성 설명으로 전달.
- 텍스트·아이콘 대비는 테마 계약에 맞춰 측정. 투명 배경은 밝고 어두운 바탕화면 모두에서 확인.
- 행 메뉴·완료·필터의 클릭 영역은 최소 28px, 주요 상단/추가 동작은 32px 이상을 목표로 DPI와 실제 창 여유에 맞춰 검증.

## 6. 단계별 실행 계획

| 단계 | 작업 | 주요 파일 | 검증·종료 조건 |
|---|---|---|---|
| A. 기준 확보 | 긴 제목·완료·읽기 전용·기한 경과·빈 목록·지연 샘플과 다크/라이트 캡처 확보 | 현재 QA Host 및 관련 테스트 | 실제 데이터 기반 추가 관찰, 기존 실패는 별도 기록 |
| B. 의미와 탐색 | 접기/펼치기 라벨, 넓은 창 상단 라벨, 메뉴 그룹·포커스 순서 정돈 | unified_widget_mode.py, locales/ | 폭·언어별 의미 유지, 기존 동작 회귀 없음 |
| C. 처리 안정성 | 갱신 전 앵커·포커스 저장/복원, 항목명 피드백, 실행 취소 포커스 보호 | unified_widget_mode.py | 완료/실패/외부 갱신·사라진 항목의 포커스 및 스크롤 검증 |
| D. 정보·꾸미기 | 제목/시간/상태 위계, 문맥별 빈 상태, 설정 명칭·미리보기 일치 | unified_widget_mode.py, widget_customization_dialog.py, density/typography/theme | 설정 취소·재시작 보존, 읽기 영역 축소 없음 |
| E. 성능·인수 | 대량 목록 측정, 긴 세션·DPI·다중 모니터·스크린 리더 수동 검증 | 관련 UI와 기존 테스트 | 기준 충족 후 공개 변경에 필요한 별도 빌드·배포 검증 |

DB 스키마·GCal 동기화 엔진은 이 계획의 UI 개선 범위에서 변경하지 않습니다. 로직 변경이 필요하면 기존 유스케이스·상태 처리기에 위임합니다. 새 app 상태는 app_initializer에서, 새 창 상태는 해당 생성자에서 초기화합니다. 저장 키 변경은 기존 값 호환과 취소 동작을 함께 설계합니다.

## 7. 검증 매트릭스와 측정 목표

### 반드시 확인할 조합

- 창: 320×480, 360×560, 420×520, 760×600. 최소 크기와 폰트에 의해 더 커질 경우 실제 크기와 원인을 기록.
- DPI: Windows 100%, 125%, 150%, 200%, 서로 다른 DPI의 모니터 이동.
- 표현: 기본 라이트/다크, 사용자 스킨, compact/standard/comfortable, 모든 기본 배치, 달력 펼침/접힘.
- 언어: 한국어·영어·독일어의 긴 라벨, 일본어·중국어, 아랍어 방향성. 새 키는 번들 19개 로케일 구조 동기화.
- 데이터: 0/3/30/100/300개, 긴 제목, 종일·시간 일정, 읽기 전용 구독, 완료·진행 중, 기한 경과·기한 없음, 부분 로딩·지연.
- 상태: 추가/편집 후 복귀, 빠른 완료·실행 취소, 저장 실패, 백그라운드 갱신, 설정 적용·취소, 트레이 재개, 앱 재시작.

### 수용 기준

| 항목 | 목표 및 측정법 |
|---|---|
| 날짜·유형 이해 | 내부 시나리오에서 도움말 없이 선택 날짜·유형·완료 포함 상태 설명 가능. 사용자 검증 전에는 가설로 기록 |
| 추가 경로 | 특정 유형에서는 주요 추가 버튼 한 번으로 해당 다이얼로그, 전체에서는 유형 선택 1단계 추가 |

| 저장 호환 | 기존 filter/skin/layout/geometry/visibility 설정 유지, 꾸미기 취소로 설정 변화 없음 |

## 8. 제외·후속 과제

- 검색·태그·전역 단축키·매크로·자동 우선순위 추천: 현재 흐름 안정화 후 실제 사용 요구로 판단.
- 가상 목록·전면 모듈 재분리: 대량 데이터 측정에서 필요성이 입증될 때 별도 설계.
- 여러 위젯의 그룹 배치나 KeyDeck 변경: 개별 오버레이 작업으로 분리.
- 구현·커밋·빌드·배포: 이번 계획 수립에 포함되지 않으며 각각 검증 완료 상태를 구분.

권장 시작 범위는 B+C입니다. 라벨과 탐색을 정돈하고 목록 읽기·처리 맥락을 보존한 뒤, D의 시각 개선과 E의 성능 결과를 평가합니다.
