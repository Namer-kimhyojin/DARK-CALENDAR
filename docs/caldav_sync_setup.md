# CalDAV 연결 (iCloud · 네이버 · Yahoo · Zoho · Fastmail)

상단 **설정** 메뉴의 **캘린더 및 동기화 → 캘린더 · 계정 및 동기화**를 열면 **캘린더 관리** 창이 열린다.
**연결 및 구독** 탭의 **다른 서비스 연결**에서 **서비스 목록 펼치기**를 누르면 연결하지 않은 서비스 카드가 보인다.
연결한 서비스는 목록을 펼치지 않아도 카드가 표시되고 상태·마지막 갱신을 확인할 수 있다.

1. 연결할 서비스 카드에서 **계정 연결**(연결 후에는 **연결 설정**)을 누른다. 서비스별 연결 창이 열린다.
2. **1. 계정 연결** 탭에서 계정과 암호를 입력하고 **연결 확인 · 캘린더 찾기**를 누른다. Zoho는 먼저 **계정 데이터센터 서버**를 고른다.
3. **2. 캘린더 선택** 탭에서 가져올 캘린더를 체크한 뒤 **선택 저장**한다.
4. **지금 동기화**로 확인한 후 **5분마다 자동 동기화**를 켠다. 기본 간격은 5분이며 연속 실패 시 최대 60분까지 늘어난다.

## 서비스별 조건

| 서비스 | 서버 | 인증 | 지원 범위 |
|---|---|---|---|
| iCloud | `https://caldav.icloud.com/` | Apple 계정 이메일 + 앱 전용 암호 | 개인 일정 양방향. 반복·초대 일정은 읽기 전용 |
| 네이버 | `https://caldav.calendar.naver.com/` | 네이버 ID + 비밀번호; 2단계 인증 사용 시 애플리케이션 비밀번호 | 읽기 전용. Windows 연결 허용 여부는 서비스 정책에 따름 |
| Yahoo Calendar | `https://caldav.calendar.yahoo.com/` | 계정 이메일 전체 주소 + Yahoo 앱 암호 | 개인 일정 양방향. 반복·초대 일정은 읽기 전용. Yahoo! JAPAN 계정은 지원하지 않음 |
| Zoho Calendar | 계정 데이터센터별 `https://calendar.zoho.<지역>/.well-known/caldav` (com·eu·in·com.au·jp·com.cn, zohocloud.ca, sa) | 계정 이메일 전체 주소 + 암호; 2단계 인증 사용 시 앱 전용 암호 | 개인 일정 양방향. 반복·초대 일정은 읽기 전용. Zoho 웹 설정에서 CalDAV에 쓸 캘린더를 먼저 선택해야 함 |
| Fastmail | `https://caldav.fastmail.com/` | 계정 이메일 전체 주소 + CalDAV 접근 권한이 있는 앱 암호 | 개인 일정 양방향. 반복·초대 일정은 읽기 전용. 외부 캘린더 클라이언트를 지원하는 요금제 필요 |

서버 주소는 앱에 고정되어 있으며 HTTPS(443) 주소만 허용한다. 서비스별 인증 안내: [Yahoo](https://help.yahoo.com/kb/SLN4707.html), [Zoho](https://www.zoho.com/calendar/help/setup-caldav-sync.html), [Fastmail](https://www.fastmail.help/hc/en-us/articles/1500000278342-Server-names-and-ports)

Apple 앱 전용 암호는 이중 인증을 설정한 계정에서 발급한다. 기본 Apple 암호를 바꾸면 앱 전용 암호도 취소되므로 다시 발급해야 한다. [Apple 안내](https://support.apple.com/en-us/102654)

네이버는 공식 안내에서 Mac의 일정 생성·수정·삭제를 지원하지 않는다고 설명하며 Windows 양방향 지원을 보장하지 않는다. 본 구현은 읽기 전용으로 제한하고 플랫폼 제한을 우회하지 않는다. 2단계 인증을 사용하는 단체 ID는 애플리케이션 비밀번호를 지원하지 않아 연결할 수 없다. [네이버 안내](https://help.naver.com/service/5620/contents/2426?lang=ko&osType=COMMONOS)

## 데이터와 충돌

- 일정 조회 범위는 지난 120일~앞으로 400일이다. **캘린더 관리** 창 **연결 및 구독** 탭의 **공통 설정 → 일정 표시 시간대**에서 변경하며, 저장한 값이 없으면 이 PC의 시간대를 사용한다. 기존 `gcal_timezone` 설정을 여러 서비스가 함께 사용한다. 진행 중인 동기화가 끝난 뒤 저장할 수 있고 다음 동기화부터 반영된다.
- 반복 일정은 개별 회차로 표시한다. 반복·초대 일정의 수정·삭제는 원래 서비스에서 수행한다. 초 단위 등 과도하게 많은 반복 회차는 확장 전에 제한한다.
- 모든 REPORT 응답을 검증한 뒤 해당 캘린더에 반영한다. 부분 응답·잘못된 XML/ICS를 정상 빈 목록으로 간주하지 않는다.
- 수정·삭제에는 ETag 조건을 적용한다. 생성은 고정 UID/리소스 경로와 `If-None-Match`로 재시도 중복을 막는다.
- 양쪽을 수정했다면 서비스 연결 창의 **3. 확인할 문제** 탭에서 내용을 비교하고 **내 변경 유지** 또는 **서비스 내용 적용**을 선택한다. 비교 후 로컬 내용이 바뀌었으면 오래된 선택은 적용하지 않는다.
- 원격에서 삭제된 일정은 로컬에 보존한다. 자동으로 다시 생성하지 않는다.
- 원격 변경이 있는 삭제와 조회 전용 일정 삭제는 자동 재시도를 멈추고 수동 확인을 기다린다. 원격 변경이 있는 삭제는 '원격 일정 다시 가져오기'(삭제 대기를 지우고 바로 동기화) 또는 '그래도 삭제'(원격 제목·시간 확인 후 그 버전만 삭제)를 고른다. 조회 전용 일정과 선택 해제·읽기 전용 캘린더에서 기다리는 삭제는 '목록에서 제거'만 할 수 있고, 원격 일정은 남는다.
- 서비스·계정·캘린더의 연결 기록을 분리한다. Google의 이전 필드가 남아 있어도 Outlook/CalDAV 소유 일정을 Google에 전송하지 않는다.
- 연결 해제와 캘린더 선택 해제는 원격 원본을 삭제하지 않는다. 캘린더 이동·서비스 간 자동 복사는 지원하지 않는다.
- 로컬에서 지정한 캘린더 이름·색상·표시 설정을 보존한다.

## 암호 저장

Windows DPAPI CurrentUser로 암호화한 별도 파일을 앱 데이터 폴더에 원자적으로 저장한다. 계정 확인과 캘린더 검색 성공 후에만 저장한다. QSettings·로그·진단 문서에는 암호를 저장하지 않는다. 입력칸은 기본적으로 암호를 숨기며 연결 작업 시작 후 비운다. 연결 해제 시 해당 계정의 암호화 파일을 삭제한다.

## 검증 경계

프로토콜·변환·공통 엔진·임시 DB/설정 UI를 모의 서비스로 검증했다. 실제 iCloud·네이버·Yahoo·Zoho·Fastmail 계정의 로그인과 원격 저장은 아직 수행하지 않았다. 암호는 설정 화면에서만 직접 입력하고 채팅이나 스크린샷에 공유하지 않는다.

ETag 목록을 조회한 뒤 변경된 일정 본문만 `calendar-multiget`으로 내려받는다. 계정·캘린더별 캐시는 앱 재시작 후에도 재사용한다. 서버가 multiget을 지원하지 않으면 전체 본문 조회로 돌아간다. RFC 6578 sync-token 기반 변경 목록 조회는 후속 개선 대상이다.

서버가 일정 파일 주소를 바꾸면 저장된 UID·반복 회차가 일치하고 이전 주소가 실제 404인 경우에만 재연결한다. 로컬 일정 ID·충돌 기준·삭제 대기를 보존하며, 삭제 전 ETag가 달라졌다면 삭제를 보류한다. 같은 주소에 다른 UID가 생긴 경우 수정·삭제를 멈추고 문제로 표시한다. 이전 버전에서 UID를 기록하지 않은 일정은 정상 동기화 후부터 주소 변경을 복구할 수 있다. 이미 주소가 바뀐 오래된 연결은 안전하게 추정할 수 없어 자동 병합하지 않는다.

변경분 다운로드와 주소 복구는 모의 서버로 검증했다. 실제 계정 및 Store 설치판 검증은 별도 단계다. [후속 검증 기록](ux-audit/calendar-sync-followup-2026-10-05.md)
