# 국제화 (i18n) 규칙

## 개요

`infrastructure/i18n.py` 가 런타임 번역을 담당합니다.
UI 문자열은 하드코딩하지 않고 반드시 `t()` 함수를 사용합니다.

## 기본 사용법

```python
from calendar_app.infrastructure.i18n import t

# 기본 패턴: t(key, fallback)
label = t("menu.system", "시스템")
title = t("dialog.task_create", "태스크 만들기")
```

`fallback`은 번역 키가 없을 때 표시되는 기본값(한국어)입니다.

## 로케일 파일 구조

```
locales/               ← 번들 로케일 (배포 포함)
  ko.json              ← 한국어 (기본)
  en.json              ← 영어
  ja.json              ← 일본어
  ...
LOCALAPPDATA/kimhyojin/Dark Calendar/locales_user/   ← 사용자 오버라이드
  ko.json              ← 사용자 커스텀 한국어 (번들보다 우선)
```

## 로케일 관련 API

```python
from calendar_app.infrastructure.i18n import (
    t,
    list_available_locale_codes,   # 사용 가능한 언어 코드 목록
    get_locale_display_name,       # 코드 → 표시 이름 ("ko" → "한국어")
    resolve_locale_file_path,      # 언어 코드 → 파일 경로
    get_user_locales_dir,          # 사용자 로케일 디렉터리 경로
)
```

## 런타임 언어 전환

`presentation/main_window/top_menus/system_menu.py`의 `build_system_menu()`에서
언어 선택 메뉴를 빌드합니다. 선택 시 `QSettings["language"]`에 언어 코드를 저장하고 재시작 안내.

`I18nManager.apply_application_locale()`는 `QApplication` 생성 후에도 호출해야 합니다.
모듈 import 시점에는 앱이 없어 RTL 설정을 적용할 수 없습니다. `bootstrap.run()`이 앱 생성 직후
방향과 Qt 번역을 적용합니다. 공통 버튼 7종(확인·취소·저장·적용·닫기·예·아니오)은 한국어를 뺀
모든 언어에서 Qt `qtbase` 카탈로그 번역이 우선하고, 카탈로그가 없는 언어(hi·id·th·vi)만 앱 번역에
`&` 니모닉을 붙여 씁니다. 원문 언어인 한국어는 Qt 카탈로그 뒤에 앱 번역을 설치해 기존 단어를
니모닉 없이 유지합니다. 버튼 로케일 값에는 `&`를 넣지 않습니다.
첫 실행 언어는 `QLocale.system().uiLanguages()` → 지역 형식(`name()`) → `en` 순서로 정합니다.
`QLocale.setDefault()`는 시스템 언어·문자 체계가 UI 언어와 같으면 시스템 지역(en_GB, pt_PT 등)을 유지합니다.
월·요일·언어별 날짜 문자열에는 `QLocale().toString(...)`을 사용합니다.
`QDate`/`QDateTime.toString(...)`만 호출하면 명시한 월·요일 패턴이 영어로 남을 수 있습니다.
요일·월 이름만 필요하면 `presentation/locale_names.py`의 `weekday_name()`·`weekday_names()`·
`month_name()`(독립형 이름)을 씁니다. 요일 이름용 로케일 키는 두지 않습니다.
기본 로컬 캘린더(`local::기본`)의 이름은 저장값을 바꾸지 않고 `calendar_display_name()`으로 표시합니다.

`zh-Hant-TW`, `zh_HK`, `pt_BR` 등은 `canonical_locale_code()`로 정규화합니다.
`zh`는 `zh-CN`의 별칭입니다. 저장된 언어가 `zh`여도 런타임은 `zh-CN.json`을 읽으므로 `locales/zh.json`은
화면에 쓰이지 않습니다. 키 구조를 맞추는 검사 때문에 파일은 유지하며, 중국어 간체 수정은 `zh-CN.json`에 합니다.
사용자 번역 파일을 덮어쓰지 않으며, 누락·깨진 문구와 키워드 인수로 형식화할 수 없는 문구는
같은 언어 번들 → 영어 → 코드 기본값 순서로 대체합니다. 레거시 별칭도 각 단계에서 해석합니다.

## 새 번역 키 추가 절차

1. `locales/ko.json`에 한국어 키-값 추가
2. `locales/en.json`에 영어 번역 추가
3. 코드에서 `t("새.키", "한국어 fallback")` 사용
4. 나머지 번들 언어에도 같은 키와 placeholder 구조를 유지합니다. 번역이 준비되지 않은 신규 키는 영어 값을 사용하고, 전체 번역 완료로 기록하지 않습니다.
5. 런타임은 현재 언어 → 해당 언어의 번들 → 영어 → 코드의 `fallback` 순서로 찾습니다.

## 용어집과 번역 검토 상태

`scripts/i18n_glossary.json`은 언어별 UI 용어집입니다. 저장·취소·일정·일반업무·지시사항·초집중 모드·D-Day,
상태와 중요도 같은 핵심 용어 40개의 영어·한국어 원문과 언어별 번역을 담습니다. 번역이 목록이면 모두
허용 형태이고 첫 항목이 기본형입니다. 사람이든 AI든 번역자는 번역 전에 이 파일을 확인하고 같은 용어를
써야 하며, 번역 도구도 이 파일로 내보내기 문맥과 경고를 만듭니다(형식과 도구 동작은 아래 '읽기 전용 점검'의
번역 도구 문단). 용어를 바꿀 때는 용어집과 그 언어 파일의 기존 문구를 함께 고칩니다. `zh`는 `zh-CN` 항목과 같습니다.

2026-11 배치 E에서 바뀐 비한국어·비영어 값은 모두 AI 초안입니다. 이 값들은 `scripts/i18n_pending_review.json`에
`machine_translated`로 남아 있으며, 원어민이 검토하기 전에는 번역 완료로 기록하지 않습니다. 검토를 마친 값은
상태 옵션 없이 `--import-review`로 적용하거나 대기 목록에서 지웁니다. `zh.json`은 `zh-CN.json`의 값과 검토 상태를
따라갑니다.

## 로케일 JSON 형식

```json
{
  "menu.system": "시스템",
  "menu.widget_clock": "디지털 시계",
  "dialog.task_create": "태스크 만들기",
  "label.today": "오늘"
}
```

런타임은 위와 같은 dotted flat 키와 중첩 객체를 모두 지원합니다. 기존 키의 표현은 유지하고,
새 네임스페이스는 `scripts/i18n_sync.py`의 정규화 결과에 맞춘 중첩 객체를 사용합니다.
예를 들어 `t("sync_redesign.workspace_title", ...)`는 `"sync_redesign": {"workspace_title": ...}`로 저장합니다.
새 키의 구조·placeholder 검사와 기존 파일 전체의 canonical 형식 검사는 구분합니다.

## 주의사항

- `t()` 함수는 현재 로드된 로케일에서 키를 검색합니다
- 현재 언어와 번들·영어에도 키가 없으면 코드의 `fallback` 반환 (빈 문자열 아님)
- `locales/` 디렉터리의 파일은 `read_text_with_legacy_fallback()`으로 읽습니다 (구버전 인코딩 호환)
- 사용자 로케일 파일이 번들 파일보다 우선합니다 (`prefer_user=True`)
- '현재 언어 파일 열기'는 `locales_user/.base/<code>.json`에 번들 사본도 저장합니다. 사용자 파일 값이
  이 사본과 같으면 수정하지 않은 값으로 보고 현재 번들 값을 씁니다 (번들 수정이 사용자에게 전달됨)

## 읽기 전용 점검

```powershell
.venv/Scripts/python.exe scripts/i18n_sync.py --base ko --limit 3
.venv/Scripts/python.exe scripts/audit_i18n.py --json artifacts/i18n-audit.json
.venv/Scripts/python.exe scripts/validate_i18n_ui.py
.venv/Scripts/python.exe scripts/validate_i18n_ui.py --theme light --scale 2 --locales ar de fr hi ja zh-TW
```

`audit_i18n.py`는 구조·중복 키·정규 형식·문자 깨짐·한글 잔존·서식 지정자와 리터럴
`t()`/`_t()` 호출의 누락 키를 검사합니다. 로케일과 사용자 설정은 수정하지 않습니다.
영어 값과 같은 문구는 별도 검토 후보입니다. 공용 단어·제품명도 포함할 수 있으므로
구조 검사 통과나 검토 후보 수를 전체 현지어 번역 완료율로 기록하지 않습니다.
템플릿 도움말의 `{time:%H:%M}`, `|italic`, `{if ...}` 등 실행 문법은 번역하지 않습니다.
UI 캡처 도구는 임시 INI·앱 데이터와 예시 구성을 사용하며 실제 사용자 설정 보존을 확인합니다.
설정 격리 도우미는 `scripts/isolated_settings.py`입니다.

같은 감사는 품질 검토 항목도 점검별로 보고합니다: `?` 문자 깨짐, 여러 언어에 남은 옛 영어,
번역문 속 영어 기능어, 영어 대비 지나치게 짧은 번역(경고 누락), HTML 태그·줄바꿈 수,
`*_format` 키의 Qt 날짜 토큰, 다른 문자 체계, 보호 용어(Air Calendar·파일 이름·OAuth 코드·
단축키 글자·`HH:mm`), QLocale과 다른 요일·월 이름, UI 호출에 들어가는 한글 리터럴, 비리터럴 `t()` 키,
영어 원문이 바뀌었는데 그대로인 번역(원문 해시 비교)과 번역 검토 대기 수입니다.
UI 호출 밖 한글 리터럴(파서 문법·검색어·DB 값·도우미 함수 인자)은 `hangul_literal`로 보고만 합니다.
현재 항목은 `tests/fixtures/i18n_audit_baseline.json`에 기록되며 테스트는 **새 항목**과
기준선에 남은 **고쳐진 항목**에서 실패합니다. 검토를 마친 변경이나 수정 뒤에는 기준선을 다시 만듭니다.

```powershell
.venv/Scripts/python.exe scripts/audit_i18n.py --update-baseline
.venv/Scripts/python.exe -m pytest -q tests/test_i18n_audit.py
```

원문 변경 항목은 해당 번역을 고칠 때까지 기준선 갱신 뒤에도 남습니다. 번역이 바뀔 필요가 없을 때만
`--update-baseline --accept-drift`를 씁니다. 독일어·아랍어 UI에서 주요 대화상자의 한글 노출은
`tests/test_i18n_leak_smoke.py`가 `tests/fixtures/i18n_leak_allowlist.json`과 비교하며,
`I18N_LEAK_UPDATE=1`로 같은 테스트를 실행하면 허용 목록을 다시 씁니다.
테스트 세션의 UI 언어는 `tests/conftest.py`가 격리된 설정에 `ko`로 고정합니다.

`i18n_sync.py --fill-missing --auto-translate`는 영어 원문만 보호 토큰을 가린 뒤 번역하고 복원을 확인합니다.
세 단어 이하 짧은 라벨은 기계 번역하지 않고 영어로 둡니다. `en.json`에 없는 키는 한국어를 복사하거나
번역하지 않고 비워 둔 채 `no_english`로 남깁니다. 영어로 채운 키와 기계 번역 키도
`scripts/i18n_pending_review.json`(로케일 폴더 밖)에 검토 대기로 남습니다.
`--export-review review.json`은 en·ko·코드 위치와 `context`(코드 파일 이름으로 만든 화면 힌트 `screen`,
같은 상위 키의 이웃 키 최대 5개와 그 영어·현재 번역 `neighbors`, 원문에 쓰인 용어집 항목 `glossary`)를
내보냅니다. `translation`을 채운 파일은 `--import-review review.json`으로 적용합니다. placeholder·보호 용어가
다르거나 제품명·파일 이름에 글자가 붙으면 적용하지 않습니다. 사람이 검토한 값은 검토 대기에서 빠지고,
기계·AI 초안은 `--review-status machine_translated`를 붙여 적용해 그 상태로 대기에 남깁니다.
`no_english` 키는 영어 번역을 먼저 넣습니다.
언어별 용어집 `scripts/i18n_glossary.json`(없어도 동작)은
`{"version": 1, "terms": {id: {"en", "ko", "note"}}, "locales": {code: {id: 번역}}}` 형식입니다.
용어의 영어 단어가 원문에 단어 단위로 있는데 번역에 그 언어의 용어가 없으면 가져오기는 적용 항목의
`warnings`로 알리고(거부하지 않음), 자동 번역은 기계 번역 값을 두고 사유를 `glossary_check`로 남깁니다.
도구는 기존 로케일·검토 대기 파일의 줄바꿈(CRLF/LF)을 유지하고 새 파일은 LF로 씁니다.
