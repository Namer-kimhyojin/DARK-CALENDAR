# Dark Calendar Promotion Kit

Official website: <https://namer-kimhyojin.github.io/DARK-CALENDAR/>

Microsoft Store: <https://apps.microsoft.com/detail/9mxq08rf22k8>

GitHub: <https://github.com/Namer-kimhyojin/DARK-CALENDAR>

## Campaign assumptions

- Goal: increase product awareness and qualified visits to the Microsoft Store listing.
- Primary audience: Windows users who want schedules, tasks, and glanceable information visible without repeatedly opening apps.
- Secondary audience: productivity enthusiasts, remote workers, students, and users who customize desktop layouts.
- Timeline: four-week organic campaign, reusable after every release.
- Budget: zero-to-low budget. Paid promotion can be added after organic messages show consistent engagement.

## Campaign concept

Campaign name: **Your Desktop, Your Time**

Core message: **Dark Calendar puts your calendar and essential widgets directly on the Windows desktop, with the freedom to move, resize, arrange, and recolor everything around the way you work.**

Supporting messages:

1. Desktop-first: schedules, tasks, clocks, weather, D-Day, and other widgets remain visible where work happens.
2. Personal layout: every element can be moved and resized; calendar-first, task-first, and widget-first layouts are all possible.
3. Personal color system: themes, accents, panels, and widget styling can be tuned to the user.
4. One connected workflow: tasks, routines, focus sessions, optional Google Calendar sync, printing, and multilingual UI live in one Windows app.

## Channel strategy

| Channel | Role | Recommended content | Effort |
|---|---|---|---|
| Official website | Conversion | Feature proof, screenshots, Google setup guide, Store CTA, share buttons | Low |
| GitHub | Trust and discovery | Product-led README, release notes, screenshots, open-source proof | Low |
| X / Threads | Awareness | Short benefit-led posts and single screenshots | Low |
| LinkedIn | Consideration | Desktop-workflow story, remote-work and productivity angle | Medium |
| Reddit / productivity communities | Feedback and discovery | Honest build story, use cases, GIF or screenshot; follow each community's rules | Medium |
| YouTube Shorts / Instagram Reels | Demonstration | 20–30 second move, resize, recolor, and layout transformation | Medium |
| Microsoft Store | Conversion | Keep screenshots, description, version notes, and keywords aligned with the website | Medium |

Do not post the same text repeatedly or enter communities only to drop a link. Lead with a concrete workflow, disclose that you built the product, and reply to questions.

## Creative directions

Use the existing assets so every post looks connected to the official website:

- `docs/assets/desktop-customization.webp`: hero creative for move, resize, layout, and color.
- `docs/assets/screenshots/widget-manager.png`: widget variety and multiple-instance story.
- `docs/assets/screenshots/focus-mode.png`: focus and Pomodoro story.
- `docs/assets/google-calendar-setup.webp`: beginner Google Calendar education.
- `docs/assets/og-dark-calendar.png`: general link preview and campaign cover.

For screenshot posts, blur or replace any personal schedule, account, location, or notification content before publishing.

## Success metrics

Primary KPI: qualified visits and acquisitions reported by Microsoft Store during the four-week campaign.

Secondary KPIs:

- Website link clicks reported by each social platform.
- Saves, shares, and meaningful comments per post.
- GitHub repository views, unique visitors, stars, and release downloads.
- Questions about setup or features, grouped by theme for homepage improvements.
- Store ratings and reviews, without incentivizing positive-only feedback.

Review weekly. After four weeks, retain the top two messages and top two visuals, pause weak variants, and create the next cycle from actual questions and user layouts.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Posts look like generic calendar advertising | Lead every creative with the desktop-first difference: direct placement, free move/resize, custom layout, and color. |
| Community posts are treated as spam | Read the community rules, disclose that you built the app, share a useful workflow first, and post links only where allowed. |
| Screenshots expose private information | Use the approved website screenshots or blur names, accounts, locations, and schedule details before publishing. |
| Promotion promises features beyond the public build | Check the current Store version and website before each campaign cycle; update copy and screenshots together. |

## Immediate next steps

1. Publish the Week 1 launch copy with `desktop-customization.webp` on the product's active social account.
2. Reuse the same message in a longer LinkedIn post, adjusting the opening to the audience's workflow problem.
3. Update Microsoft Store screenshots and description when the next product release changes visible functionality.
4. Record platform metrics once per week in a simple campaign log.
5. After four weeks, select the strongest message and image using actual clicks, saves, shares, Store data, and user questions.

## Publishing checklist

- Confirm the website and Store links work before posting.
- Use one clear CTA per post.
- Match the post language to the linked homepage language.
- Disclose your relationship to the product in communities.
- Never include OAuth credentials, tokens, private calendar data, or identifiable screenshots.
- Keep product claims aligned with the current public release.
